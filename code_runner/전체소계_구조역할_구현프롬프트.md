# 전체·소계·파생 셀 구조 역할 구현 프롬프트

아래 전체 내용을 구현 담당 AI에게 그대로 전달한다.

```text
현재 /root/nais-link 저장소의 part/code 브랜치에서 code_runner만 수정하라.
main, doc_parser, app은 수정하지 마라.

목표:
보고서 표와 코드 실행 표를 대조할 때, 일반 상세 셀(detail)과 전체·소계·파생 셀을 구분해 잘못된 자동 비교를 막아라.

기존 구조:
- code_runner/table_models.py
- code_runner/table_alignment.py
- code_runner/table_workflow.py
- code_runner/test_table_workflow.py
- code_runner/표대조_5단계판정_구현명세.md
- 기존 workflow.evaluate(), comparison.compare_evidence()는 값 판정 게이트이므로 재사용한다.
- 값 비교 로직을 새로 복제하지 마라.

구현 요구사항:

1. table_models.py에 셀 구조 역할 Enum을 추가하라.

class CellRole(str, Enum):
    DETAIL = "detail"
    SUBTOTAL = "subtotal"
    TOTAL = "total"
    DERIVED = "derived"
    UNKNOWN = "unknown"

2. ReportTableCell과 ExecutionTableCell에 cell_role을 추가한다.
기본값은 UNKNOWN으로 둔다. 역할 근거가 없는 셀을 DETAIL로 간주하면
잘못된 자동 match가 만들어질 수 있다.
기존 fixture와 호출부는 명시적으로 CellRole.DETAIL을 전달하도록 마이그레이션한다.

3. table_alignment.py에서 셀 연결과 값 판정 전에 구조 역할을 검사한다.

- DETAIL ↔ DETAIL:
  기존 의미 대조와 허용오차 대조를 진행한다.

- TOTAL ↔ TOTAL 또는 SUBTOTAL ↔ SUBTOTAL:
  직접 대응 실행 출력이고,
  현재 QuantitySemantics가 제공하는 metric/formula/period/population/denominator가
  모두 exact일 때만 기존 값 대조를 진행한다.
  filters/missing_value_policy/weight는 현재 모델에 없으므로 이 변경에서 추측하거나
  임시 문자열 비교를 추가하지 마라.

- DETAIL ↔ TOTAL/SUBTOTAL, TOTAL ↔ DETAIL, TOTAL ↔ SUBTOTAL,
  SUBTOTAL ↔ DETAIL:
  자동 값 비교를 수행하지 않는다.
  ReviewStatus.NOT_COMPARABLE을 반환한다.
  reason code는 STRUCTURAL_ROLE_MISMATCH를 사용한다.
  absolute_difference와 relative_difference는 만들지 않는다.

- DERIVED:
  직접 실행 출력이 아니라 여러 출력값으로 재구성된 후보다.
  자동 match/mismatch로 확정하지 않는다.
  ReviewStatus.NEEDS_HUMAN_REVIEW을 반환하고
  reason code는 DERIVED_CANDIDATE_REQUIRES_REVIEW을 사용한다.

- UNKNOWN:
  구조 역할을 증명할 수 없으므로 자동 match/mismatch를 만들지 않는다.
  한쪽 또는 양쪽이 UNKNOWN이면 ReviewStatus.NEEDS_HUMAN_REVIEW,
  reason code STRUCTURAL_ROLE_UNKNOWN을 사용한다.

4. “전체”, “합계”, “소계”라는 문자열만 보고 무조건 자동 분류하지 마라.
파서 또는 실행 어댑터가 명시적으로 전달한 cell_role을 신뢰한다.
명시 근거가 없으면 UNKNOWN을 유지한다. 문자열만 보고 UNKNOWN을 DETAIL,
TOTAL 또는 SUBTOTAL로 자동 변경하지 마라.

5. CellComparison 결과에 다음을 보존한다.
- report_cell_role
- execution_cell_role
- relation 또는 structural_reason
- 기존 reason_codes
- report/output locator

6. test_table_workflow.py에 아래 테스트를 추가한다.
- DETAIL ↔ DETAIL은 기존 match/mismatch 흐름 유지
- TOTAL ↔ TOTAL은 의미 조건 exact일 때만 값 비교
- DETAIL ↔ TOTAL은 STRUCTURAL_ROLE_MISMATCH + 자동 값 비교 금지
- TOTAL ↔ SUBTOTAL도 STRUCTURAL_ROLE_MISMATCH + NOT_COMPARABLE
- DERIVED 셀은 값이 같아도 NEEDS_HUMAN_REVIEW
- UNKNOWN 셀은 자동 match 금지
- 역할을 주지 않은 셀은 기본값 UNKNOWN으로 NEEDS_HUMAN_REVIEW
- 기존 모든 table/scalar/triple 테스트가 통과

7. code_runner/표대조_5단계판정_구현명세.md에
“전체·소계·파생 셀 구조 역할 규칙” 섹션을 추가한다.
이 규칙은 표 구조가 정형화된 현재 입력에서만 적용하며,
가로·세로 피벗 변환 기능은 추가하지 마라.

검증:
uvx ruff check code_runner
uv run --with pytest pytest code_runner

작업 후 변경 파일, 테스트 결과, 남은 연결 범위를 간단히 보고하라.
```
