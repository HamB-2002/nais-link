# 두 표 대조 통합 구현 최종 프롬프트

> 사용처: 팀원이 만든 보고서 표 artifact와 코드 재실행 표 artifact를 합친 뒤, `code_runner/`의 대조 엔진을 구현·통합할 때 아래 전체를 그대로 AI 코딩 도구에 입력한다.

```text
당신은 NAIS Link의 code_runner 담당 구현자다.

목표는 보고서 파서가 만든 표 A와 승인된 분석 코드를 재실행해 얻은 표 B를 자동 대조하는 것이다. 단순히 같은 행·열의 숫자를 빼지 말고, 두 셀이 같은 연구 질문과 같은 계산을 나타낸다는 근거가 있을 때만 값 비교를 수행하라.

## 0. 작업 범위

- 수정 범위는 code_runner/만이다.
- doc_parser/, app/, main 브랜치의 파일은 수정하지 않는다.
- 문서 파싱, 업로드 UI, Docker 실행 환경을 새로 만들지 않는다. 이미 구조화되어 전달된 표 artifact를 입력으로 사용한다.
- Python/R/C/C++/Stata/SQL 등 분석 언어별 차이는 어댑터가 공통 artifact로 변환해 흡수한다. 공통 대조 엔진이 특정 언어의 AST·변수명에 의존하면 안 된다.
- 기존 scalar/triple/table 비교 로직과 테스트를 깨지 말고, 값 비교 규칙은 중복 구현하지 말고 기존 workflow/comparison/tolerance 정책을 재사용한다.
- LLM 추론, 변수명 유사도, 숫자값 우연한 일치는 자동 일치의 근거가 될 수 없다.

## 1. 입력과 최소 단위

입력은 아래 두 컬렉션이다.

1. ReportTableArtifact[]: 보고서에서 파싱된 표
2. ExecutionTableArtifact[]: 승인된 코드의 재실행 결과 표

최소 판정 단위는 표 전체가 아니라 다음 한 쌍이다.

보고서 셀 = panel + row_key + column_path + value + semantics + source_locator
실행 셀   = panel + row_key + column_path + value + semantics + output_locator + execution evidence

각 보고서 셀은 대응 실행 셀과의 연결 근거, 의미 10기준 대조 결과, 수치 판정 근거, 최종 상태를 모두 보존해야 한다.

## 2. 표와 셀 연결 규칙

### 2-1. 표 연결

보고서 표와 실행 표의 후보 연결 근거는 다음만 사용한다.

- 표 ID 또는 승인된 explicit mapping
- 정규화된 제목 토큰
- 공통 행·열 구조
- 대표 셀의 지표와 기간
- 코드 출력 locator 또는 명시적 재현 주석

값이 같은 셀의 개수는 표 연결 점수에 절대 사용하지 않는다.
점수는 후보 정렬용이며 최종 match/mismatch 판정 근거가 아니다.

- 최고 후보가 단일하고 최소 근거를 충족하면 표를 연결한다.
- 1등과 2등 후보가 동점 또는 ambiguity margin 미만이면 ambiguous로 남기고 자동 값 비교하지 않는다.
- 대응 실행 표가 없으면 report_only_table, 보고서 대응이 없는 실행 표는 execution_only_table로 모두 보존한다.

### 2-2. 셀 연결

연결된 표 안에서 아래 키로 셀 후보를 만든다.

normalized(panel) + normalized(row_key) + normalized(column_path[])

정규화는 대소문자·공백 정리와 승인된 동의어 매핑만 허용한다.
예: 서울/서울시/Seoul은 승인 registry의 canonical ID가 같을 때만 연결 가능하다.

- 하나의 보고서 셀 ↔ 하나의 실행 셀: matched_cell 후보
- 하나의 보고서 셀 ↔ 여러 실행 셀: needs_human_review, 후보 전부 보존
- 보고서 셀만 존재: evidence_incomplete + MISSING_EXECUTION_COUNTERPART
- 실행 셀만 존재: execution_only_cell로 별도 보존, 보고서 불일치로 단정 금지
- 사용한 mapping registry version, hash, mapping ID, 원문 alias를 결과에 기록한다.

## 3. 의미 10기준 대조

matched_cell에 한해서 아래 10개를 반드시 같은 순서로 대조한다.
각 항목은 exact / mismatch / unknown / not_applicable 중 하나이며,
report_value, execution_value, report_locator, execution_locator, reason_code를 함께 반환한다.

1. metric: 무엇을 측정하는가
2. aggregation_or_formula: 평균·합계·비율·회귀계수와 실제 산식이 같은가
3. period: 같은 연도·월·관측 구간인가
4. population: 같은 지역·표본·하위집단인가
5. denominator: 같은 분모를 사용하는가
6. filters: 같은 포함·제외 조건인가
7. missing_value_policy: 결측 제외·0 대체·대체법이 같은가
8. weight: 비가중·표본가중·사후층화 등 가중 규칙이 같은가
9. transformation: 원값·로그·표준화·지수화 등 변환이 같은가
10. unit: %, %p, 명, 원, kg 등 차원과 환산이 호환되는가

중요:
- mean(score)와 sum(score)는 aggregation_or_formula mismatch다.
- 유효 응답자와 전체 응답자는 denominator mismatch다.
- %와 ratio는 근거 있는 환산이 가능하면 unit exact로 만들 수 있지만, %와 명은 unit mismatch다.
- not_applicable은 양쪽 근거로 해당 기준이 실제 적용되지 않음을 증명할 때만 사용한다. 누락값을 exact 또는 not_applicable로 채우지 않는다.

## 4. 최종 5단계 판정: 반드시 이 우선순위를 사용

아래 상태만 decision_status로 반환한다.

1. needs_human_review
   - 표/셀 연결 후보가 경합함
   - 10개 기준에 mismatch는 없지만 unknown이 하나 이상 있음
   - 허용오차 정책이 없음
   - 임의로 첫 후보를 선택하지 않는다.

2. not_comparable
   - 연결된 셀의 10개 기준 중 하나라도 명백히 mismatch
   - 숫자가 동일해도 부여한다.
   - absolute_difference와 relative_difference는 null이다.

3. evidence_incomplete
   - 보고서 대응 실행 셀, 입력 계약, 코드 provenance, 실행 결과, 출력 locator 같은 필수 근거가 없음
   - 실행 실패·격리 실패·출력 누락은 mismatch가 아니라 이 상태다.

4. match
   - 셀 연결이 단일함
   - 10개 기준이 모두 exact 또는 근거 있는 not_applicable
   - 실행/출력 근거와 허용오차 정책이 완결됨
   - 단위 환산과 보고서 표기 자릿수 반올림 후 값 차이가 허용오차 이내

5. mismatch
   - match의 모든 선행조건을 만족함
   - 단위 환산과 반올림 후 값 차이가 허용오차를 초과함

판정 순서:

셀 연결 단일성 확인
→ 명백한 의미 mismatch 확인
→ 필수 증거·실행·출력 완결성 확인
→ 의미 unknown 확인
→ 허용오차 정책 확인
→ 단위 환산, 반올림, 절대/상대 허용오차 값 비교
→ match 또는 mismatch

이미 명확한 기간/산식 mismatch가 확인된 경우에는 실행 실패가 함께 있어도 not_comparable을 최종 상태로 남기고, 실행 실패는 보조 reason code로 보존한다.

## 5. 수치 비교 규칙

- 단위 차원이 호환될 때만 변환한다. 변환식과 원 단위를 결과에 기록한다.
- 보고서가 표시한 자릿수 기준으로 반올림한 뒤 비교한다.
- TolerancePolicy 우선순위는 report_declared > approved_metric_catalog > 없음이다.
- 정책 없음은 허용오차 0이 아니다. needs_human_review다.
- 금액·종합지수 등 연구 정의가 큰 지표에는 임의 기본 허용오차를 적용하지 않는다.
- 수치 차이는 match 또는 mismatch일 때만 산출한다. not_comparable/evidence_incomplete/needs_human_review에서는 null이다.

## 7. 반드시 작성·통과시킬 테스트

1. 평균 15와 합계 15 → not_comparable, AGGREGATION_OPERATOR_MISMATCH
2. 2025년 평균과 2024년 평균 → not_comparable, PERIOD_MISMATCH
3. 15%와 15명 → not_comparable, UNIT_DIMENSION_MISMATCH
4. 동일 의미 15.0%와 15.02%, 0.1%p 정책 → match
5. 동일 의미 15.0%와 15.2%, 0.1%p 정책 → mismatch
6. 필터·결측 처리·가중치 중 하나가 다름 → 각각 not_comparable
7. 10개 기준 중 하나가 unknown → needs_human_review, 차이 null
8. 실행 출력 셀이 없음 → evidence_incomplete, MISSING_EXECUTION_COUNTERPART
9. 동일 좌표 실행 셀이 둘 이상 → needs_human_review, 후보 둘 다 보존
10. 서울/서울시 승인 매핑은 연결되지만 승인되지 않은 유사 표기는 자동 연결하지 않음
11. %/ratio와 cm/m, kg/g은 환산 후 비교하되 환산 근거를 보존
12. 모든 결과에 reason code, 보고서 위치, 코드 위치 또는 부재 사유, 출력 위치 또는 부재 사유가 존재
13. 기존 code_runner 전체 테스트가 통과
```
