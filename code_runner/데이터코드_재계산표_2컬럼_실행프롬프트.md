# NAIS 데이터·코드 재계산표 앱 실행 프롬프트

## 목적

이 문서는 보고서와 비교하지 않고, 원본 데이터와 분석 코드만 실행해 재계산 지표를 만드는 앱용 하위 프롬프트다.

최종 웹 표시표는 정확히 두 컬럼만 가진다.

```text
지표 | 재계산값
```

전체 시스템의 보고서 파싱·표 비교·`match/mismatch` 기준은 [NAIS_LINK_코드러너_최종통합마스터프롬프트.md](../code_runner/NAIS_LINK_코드러너_최종통합마스터프롬프트.md)의 책임이다. 이 문서는 그 이전 단계인 데이터·코드 재계산과 웹 표시만 담당한다.

## 1. 입력과 금지 범위

입력은 다음 두 가지다.

1. 분석 데이터
2. 승인된 분석 코드와 실행 계약

이 문서는 다음을 입력으로 사용하지 않는다.

- 연구보고서·논문
- 보고서에 적힌 원 수치
- 표 1 또는 보고서 Claim
- 보고서 위치·페이지·표 번호
- 보고서와의 join·비교·허용오차 판정

질문은 다음 하나다.

```text
이 데이터와 이 코드가 실제 실행에서 생성한 지표와 값은 무엇인가?
```

## 2. 코드 인덱스와 Provenance

실행 전에 코드 인덱스를 만든다.

```text
입력 파일
  → 입력 열·필터·전처리
  → 함수·대입·집계·통계식
  → 출력 변수
  → 출력 파일·JSON key·stdout
```

1차로 `rg`를 사용해 입력 파일명, reader, 집계 함수, 출력 함수를 찾는다.

```bash
rg -n --hidden \
  -e 'read_csv|read\.csv|read_excel|json\.load|fopen|ifstream' \
  -e 'groupby|aggregate|mean|median|sum|count|ratio|correlation|alpha|kappa' \
  -e 'to_csv|to_json|write|save|export|print' \
  code/ analysis/ src/ R/ scripts/
```

가능하면 승인된 Tree-sitter 또는 언어별 parser로 함수·대입·호출·입력·출력 위치를 구조화한다. parser가 없거나 실패하면 `parser_status`를 manifest에 기록하고 자동 확정하지 않는다.

각 지표의 상세 결과에는 다음을 남긴다.

```json
{
  "metric_id": "lyrics.avg_eng_ratio",
  "source_language": "python",
  "source_locations": [
    {
      "path": "scripts/lyrics_analysis.py",
      "line_start": 285,
      "line_end": 307,
      "symbol": "compute_yearly_summary"
    }
  ],
  "output_locator": "output/analysis_tables/lyrics_yearly_summary.csv",
  "input_references": ["datasets/lyrics_metrics.csv"]
}
```

## 2-1. 범용 자동화 규칙

새로운 sample의 구조를 미리 알고 있다고 가정하지 않는다. 데이터와 코드가 들어오면 다음 순서로 동적으로 설정한다.

### 1. 언어·파일 형식·실행 환경 자동 탐색

확장자와 프로젝트 파일을 기준으로 언어와 실행 환경을 식별한다.

| 대상 | 우선 탐색할 단서 |
|---|---|
| Python | `*.py`, `pyproject.toml`, `requirements.txt`, `environment.yml` |
| R | `*.R`, `*.r`, `renv.lock`, `DESCRIPTION` |
| C/C++ | `*.c`, `*.cpp`, `CMakeLists.txt`, `Makefile` |
| Java | `*.java`, `pom.xml`, `build.gradle` |
| Julia | `*.jl`, `Project.toml`, `Manifest.toml` |
| MATLAB | `*.m` |
| Stata/SAS | `*.do`, `*.sas` |
| Julia·Rust·Go·셸 등 | 해당 확장자와 lockfile·build 설정 |

언어, 버전, 패키지 관리자, 빌드 명령을 확인하지 못하면 임의의 환경을 추정하지 않는다. `runtime_detection_failed`를 기록하고 사람 검토 또는 실행 실패로 처리한다.

### 2. 실행 진입점·의존성·출력 경로 자동 탐색

실행 명령은 다음 우선순위로 결정한다.

1. 제공된 실행 계약 또는 README의 명시적 명령
2. 표준 프로젝트 설정 파일의 script/entrypoint
3. 언어별 관례적 진입점(`main`, `run_*`, `if __name__ == "__main__"` 등)
4. 코드 인덱스에서 입력 reader와 출력 writer가 연결된 후보

후보가 여러 개면 임의로 하나를 선택하지 않고 후보 목록과 선택 근거를 manifest에 남긴다. 입력·출력 연결이 없는 파일, 시각화 전용 파일, 라이브러리 파일은 단독 분석 실행 대상으로 취급하지 않는다.

### 3. 코드 인덱스 기반 입력·계산·출력 추적

언어가 달라도 아래의 논리 그래프를 만든다.

```text
입력 파일·열
  → reader·필터·전처리
  → 함수·대입·집계·통계식
  → 지표 변수·그룹 변수
  → writer·파일·JSON key·stdout
```

정규식 검색만으로 연결이 확정되지 않으면 Tree-sitter 또는 언어별 parser를 사용한다. parser가 없거나 데이터 흐름이 끊기면 후보를 공식 재계산으로 확정하지 않고 `provenance_incomplete`를 기록한다.

### 4. 출력 스키마 기반 지표·그룹 자동 설정

코드가 실제 실행에서 새로 만들거나 변경한 CSV·TSV·XLSX·JSON·Parquet·stdout 결과를 우선 수집한다. 결과의 수치형 컬럼을 지표 후보로 만들고, 다음 우선순위로 그룹 컬럼을 식별한다.

1. 코드의 `groupby`, `by`, `group`, `facet`, `strata` 등에 사용된 열
2. 출력에 포함된 `Year`, `Date`, `Group`, `Category`, `Condition` 등 식별 열
3. 실행 계약에 명시된 그룹 열

최종 표시명은 다음처럼 만든다.

```text
그룹값 · 원래 출력 컬럼명
```

예를 들어 출력 행이 `Year=2025`, `Avg_Eng_Ratio=58.27`이면 `2025 · Avg_Eng_Ratio`로 표시한다. 원래 컬럼명에 단위가 포함되어 있으면 보존하고, 단위를 임의로 번역하거나 보고서 표현으로 바꾸지 않는다. 그룹을 확정할 수 없는 수치는 `group_inference_failed`로 기록한다.

### 5. 불확실한 자동 설정의 보류와 사람 검토

다음 경우에는 자동으로 지표를 만들거나 실행 결과를 성공 처리하지 않는다.

- 실행 진입점이 여러 개이고 선택 근거가 없음
- 코드가 입력 파일을 실제로 읽는지 확인할 수 없음
- 출력 파일이 실행 전부터 존재하고 실행 후 변경되지 않음
- 계산식·출력 변수·입력 열 사이의 provenance 연결이 끊김
- 여러 입력 데이터 중 어떤 파일이 분석 대상인지 확정할 수 없음
- 그룹 열이나 지표 의미를 임의 추정해야 함

이 경우에도 후보·실패 사유·발견한 파일·코드 위치는 상세 결과에 남기고, 웹 표에는 `지표 | null` 행으로 표시하거나 사람 검토 목록으로 분리한다. 추정한 값이나 임의로 선택한 지표명을 성공 결과로 저장하지 않는다.

## 3. 입력 데이터 검증

각 입력 파일에 대해 다음을 기록한다.

- 상대 경로
- `input_role`: `raw_input`, `processed_input`, `precomputed_output`
- 형식
- SHA-256
- 행·열 수
- 열 이름·자료형
- 필수 열
- 코드 선언 입력과 실행 중 실제 관찰된 입력

`processed_input`은 원자료가 아니라 이미 가공된 입력임을 표시한다. 기존 결과표를 입력으로 다시 읽어 만든 값은 `precomputed_output`으로 분류하며 원본 재계산으로 부르지 않는다.

다음이 모두 확인되어야 해당 지표의 값을 공식 또는 참고 실행값으로 채운다.

```text
declared_inputs == observed_inputs
입력 SHA-256 일치
필수 열 존재
실행 중 실제 파일 접근 확인
계산식이 입력 열을 참조
```

## 4. 하드코딩과 출력 검증

다음은 재계산으로 인정하지 않는다.

```python
result = 58.27
```

```r
reported_value <- 58.27
```

요약 행·분자·분모·표본 수·통계량을 코드에 직접 입력하고 원본 데이터를 사용하지 않는 경우 `CODE_DATA_INPUT_MISMATCH`를 기록한다.

실행 결과는 실행 전후 파일 목록과 해시를 비교한다.

```text
실행 전 output snapshot
  → 코드 실행
  → 실행 후 output snapshot
  → 새로 생성되거나 변경된 출력만 수집
```

실행 전에 이미 존재하던 CSV·JSON을 코드가 새로 생성한 결과로 착각하지 않는다.

## 5. 실행 모드

### 공식 실행

Docker에서 승인된 entrypoint와 고정 argv로 실행한다.

- 네트워크 차단
- 입력 read-only mount
- 출력 폴더만 write 허용
- CPU·메모리·시간 제한
- 고정 runtime·dependency·locale·timezone·seed
- 코드 revision·image digest·artifact hash 기록

Docker가 없으면 공식 `recomputed`로 표시하지 않는다.

### 로컬 참고 실행

개발·테스트에서는 `reference_local` 모드를 사용할 수 있다.

- 임시 작업 폴더에서 실행
- 원본 출력 파일을 덮어쓰지 않음
- `reference_only=true`
- `official=false`
- 웹 화면에 로컬 참고값임을 표시

## 6. 지표 ID와 그룹 조건

지표명만으로 지표를 식별하지 않는다. 각 상세 기록에는 `canonical_metric_key`와 `value_role`을 둔다.

### 6-1. 범용 값 역할과 canonical metric key

`value_role`은 특정 연구에 종속되지 않는 값의 역할이다.

```text
scalar, count, sum, mean, median, minimum, maximum,
proportion, percentage, ratio, rate, amount,
coefficient, effect, p_value, confidence_interval,
ci_lower, ci_upper, correlation, agreement, index,
date, period
```

같은 숫자라도 역할이 다르면 별도 지표로 저장한다. 예를 들어 계수 `-0.0698`, 효과 `-6.7%`, p값 `0.004`는 서로 join하지 않는다.

```text
{domain}.{metric}.{variant}.{value_role}[.{group_key}]
```

예:

```text
architecture.asd.att.coefficient
architecture.asd.att.effect
architecture.asd.att.p_value
```

보고서 표현·코드 변수명·출력 열 이름의 alias는 승인된 `metric_alias_registry`로만 연결한다. registry가 없거나 의미가 불확실하면 `JOIN_KEY_UNRESOLVED`와 사람 검토를 기록한다.

```json
{
  "canonical_metric_key": "lyrics.character_ratio.yearly.mean",
  "metric_aliases": ["Avg_Eng_Ratio", "평균 영문 문자 비율"],
  "metric_name": "평균 영문 문자 비율",
  "group": {"Year": 2025},
  "unit": "%",
  "value_type": "number",
  "value_role": "percentage",
  "metric_alias_registry": {"version": "v1", "mapping_id": "lyrics-ratio-001"}
}
```

그룹 식별 열은 지표 표시명에 결합한다.

```text
metric_id: lyrics.avg_eng_ratio
지표: 2025 · 평균 영문 문자 비율
```

그룹 열을 임의로 추정할 수 없으면 `group_inference_failed`를 기록하고 해당 값은 사람 검토 대상으로 둔다.

## 7. 숫자형 정규화

CSV·JSON에서 읽은 숫자 문자열은 표시 전에 숫자로 변환한다.

```text
"58.27" → 58.27
"1,255,014" → 1255014
"42.3%" → 42.3, unit="%"
"N/A" → null
```

JSON의 `재계산값`에는 숫자·문자열·null을 허용하되, 숫자로 해석 가능한 값은 반드시 JSON number로 저장한다. 변환 실패 시 원문을 버리지 말고 상세 manifest에 기록한다.

## 8. 웹 표시용 결과 계약

웹 표시용 `data_code_table.json`의 행은 아래 두 키만 가진다.

```json
{
  "schema_version": "nais-data-code-recalculation-v1",
  "sample_id": "sample-12",
  "execution_mode": "reference_local",
  "reference_only": true,
  "rows": [
    {"지표": "2015 · 총 곡수", "재계산값": 36},
    {"지표": "2015 · 평균 영문 문자 비율", "재계산값": 25.77},
    {"지표": "2025 · 평균 영문 문자 비율", "재계산값": 58.27}
  ]
}
```

`rows`의 각 객체에는 `지표`와 `재계산값` 외의 키를 넣지 않는다. 웹 화면에는 행 인덱스를 표시하지 않는다.

```json
}
```

`comparison_handoff` 규칙:

- `coordinate_hint`는 코드 실행 출력의 그룹·열·패널에서만 만든다. 보고서의 행명·열명·표 번호를 읽거나 맞춰 쓰지 않는다.
- `semantics`는 `metric`, `aggregation_or_formula`, `period`, `population`, `denominator`, `filters`, `missing_value_policy`, `weight`, `transformation`, `unit` 열 개를 모두 가진다.
- 각 의미 항목은 `raw_value`, `normalized_value`, `state`, `locator`, `extraction_method`, `reason_code`를 가진다. 코드 인덱스·실행 manifest·출력 스키마에서 확인하지 못한 항목은 임의로 채우지 않고 `state: "unknown"`과 구체적 reason code를 기록한다.
- `structural_role`은 `DETAIL`, `SUBTOTAL`, `TOTAL`, `UNKNOWN` 중 하나다. 출력 구조로 증명하지 못하면 `UNKNOWN`으로 기록한다.
- 이 문서는 코드 측 근거만 기록한다. 보고서와의 동의어 매핑·표 연결·의미 비교·허용오차·최종 판정은 수행하지 않는다.

비교용 상세 결과는 웹의 두 컬럼 표에 표시하지 않는다. 보고서 비교 단계가 이 파일을 읽는다.

## 10. 실패 처리

실패한 지표도 삭제하지 않는다.

```text
코드가 입력을 읽지 않음
  → value = null
  → run_status = analysis_failed
  → CODE_DATA_INPUT_MISMATCH

코드 출력 경로·계산 경로 없음
  → value = null
  → run_status = no_provenance_candidate

실행 오류·패키지 누락·출력 누락
  → value = null
  → run_status = execution_failed

Docker 없음
  → 공식 실행 시작 금지
  → run_status = isolation_unavailable

로컬 참고 실행 성공
  → value 기록 가능
  → run_status = reference_only
  → official = false
```

표시표는 실패 행도 `지표 | null`로 유지하고, 실패 사유는 `recalculation_records.json`과 실행 manifest에 둔다.

## 11. 완료 조건

1. 보고서 없이 데이터와 코드만 사용했다.
2. 코드 인덱스에서 입력·계산·출력 경로를 확인했다.
3. 실제 입력 파일 접근과 해시를 확인했다.
4. 실행 전후 출력 파일을 비교해 실제 생성 결과만 수집했다.
5. 모든 결과값을 숫자형으로 정규화했다.
6. 각 상세 결과에 `metric_id`, 그룹 조건, `comparison_handoff`의 좌표 힌트·구조 역할·의미 10기준 근거가 있다. 확인하지 못한 의미는 `unknown`과 reason code로 기록한다.
7. 웹 표시 JSON의 행은 정확히 `지표`, `재계산값` 두 키만 가진다.
8. 비교용 상세 결과와 웹 표시 결과를 분리했다.
9. 공식 Docker 실행과 로컬 참고 실행을 구분했다.
10. 보고서 수치와의 비교·join·`match/mismatch`는 수행하지 않았다.
