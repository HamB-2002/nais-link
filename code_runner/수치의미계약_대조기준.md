# 수치 의미 계약: 같은 `15`를 함부로 비교하지 않는 기준

## 1. 목적

보고서의 `15`와 코드 실행 결과의 `15`는 숫자 표면만 같을 수 있다.

- 보고서 `평균 15점` ↔ 실행 `합계 15점`
- 보고서 `15%` ↔ 실행 `15명`
- 보고서 `표본 평균 15` ↔ 실행 `집단별 평균의 비가중 평균 15`
- 보고서 `결측 제외 평균 15` ↔ 실행 `결측을 0으로 처리한 평균 15`

이들은 값이 같아도 **같은 연구 질문의 값이 아니므로 비교 대상이 아니다.**
숫자내력은 값 차이를 계산하기 전에 `수치 의미 계약(Quantity Semantics Contract)`을 대조한다.

## 2. 판정 원칙

```text
숫자 문자열 일치
  ≠ 지표 일치
  ≠ 산식 일치
  ≠ 비교 가능

집계 방식·대상·기간·분모·필터·결측 처리·가중치·변환이 모두 확인된 경우에만
단위 환산 → 반올림 → 허용오차 값 비교를 수행한다.
```

한 항목이라도 명백히 다르면 `not_comparable`이다. 항목이 추출되지 않았거나 코드 근거가 불충분하면 `needs_human_review`이며, 값 비교와 `match`/`mismatch` 생성을 보류한다.

## 3. Quantity Semantics Contract

Claim(보고서 값), Data Contract(데이터 의미), Evidence(코드 재실행 값)는 아래 계약을 각각 보관한다. 자연어 설명만 저장하지 않고, 비교 가능한 정규화 필드와 원문 근거를 함께 보관한다.

```json
{
  "quantity_kind": "numeric_estimate",
  "metric": "만족도 점수",
  "aggregation": {
    "operator": "mean",
    "group_by": [],
    "row_scope": "respondent",
    "weight_column": null,
    "distinct_key": null
  },
  "numerator": "sum(satisfaction_score for included respondents)",
  "denominator": "count(included respondents with non-missing satisfaction_score)",
  "filters": ["survey_wave = 2025", "region = Seoul"],
  "missing_value_policy": "exclude_missing",
  "population": "2025년 서울 응답자",
  "period": "2025년 1월~6월",
  "transformations": ["raw 1~20 score"],
  "estimate_method": "arithmetic_mean",
  "unit": "점",
  "formula_canonical": "mean(satisfaction_score) WHERE survey_wave=2025 AND region=Seoul AND satisfaction_score IS NOT NULL",
  "source_evidence": {
    "kind": "report_table_note",
    "location": "Table 3 note",
    "text": "결측 응답을 제외한 서울 응답자의 평균"
  }
}
```

### 3-1. 필수 대조 필드

| 범주 | 필드 | 예시 | 다르면 |
|---|---|---|---|
| 수량 종류 | `quantity_kind` | count, rate, mean, median, percentile, sum, ratio, p_value | `not_comparable` |
| 집계 | `aggregation.operator` | sum, mean, weighted_mean, median | `not_comparable` |
| 행/그룹 단위 | `row_scope`, `group_by` | 개인별, 기관별, 월별 평균 | `not_comparable` 또는 검토 |
| 분자·분모 | `numerator`, `denominator` | 합계/유효응답자 수 | `not_comparable` |
| 대상·기간 | `population`, `period` | 2025년 서울 응답자 | `not_comparable` |
| 필터 | `filters` | 제외 기준, 기준군, 이벤트 조건 | `not_comparable` |
| 결측 | `missing_value_policy` | 제외, 0 대체, 대치 | `not_comparable` |
| 가중치 | `weight_column` | 설문가중치, 표본가중치 | `not_comparable` |
| 중복 처리 | `distinct_key` | 개인 ID 기준 1회 | `not_comparable` |
| 변환 | `transformations` | 로그, 표준화, 인플레이션 보정 | `not_comparable` |
| 추정 방법 | `estimate_method` | 단순평균, 회귀계수, DID 추정치 | `not_comparable` |
| 표현 | `unit`, 반올림, 비교 모드 | %, %p, 원, 배 | 변환 가능 여부 확인 후 비교 |

`unknown`은 `exact`으로 추정하지 않는다. 예를 들어 코드에 `mean(score)`가 보이지만 보고서에 결측 처리 설명이 없으면 `missing_value_policy=unknown`으로 남기고 자동 일치를 금지한다.

## 4. 핵심 예시: 평균 15와 합계 15

| 항목 | 보고서 Claim | 코드 Evidence | 결과 | 이유 |
|---|---|---|---|---|
| 표면값 | `15점` | `15점` | 값만 같음 | 숫자 동일은 근거가 아님 |
| 집계 연산자 | `mean` | `sum` | `not_comparable` | 평균과 합계는 서로 다른 통계량 |
| 분모 | `유효응답자 수` | 없음 | `not_comparable` | 평균의 분모가 실행값에 없음 |
| 산식 | `sum(score) / count(valid score)` | `sum(score)` | `not_comparable` | 산식이 다름 |

출력은 아래처럼 사람이 바로 이해할 수 있어야 한다.

```json
{
  "status": "not_comparable",
  "reason_codes": [
    "AGGREGATION_OPERATOR_MISMATCH",
    "DENOMINATOR_MISMATCH",
    "FORMULA_MISMATCH"
  ],
  "reason_summary": "두 값 모두 15점이지만 보고서는 유효응답자 평균, 재실행은 점수 합계입니다. 값 비교를 수행하지 않았습니다.",
  "numeric_difference": null
}
```

## 5. 집계 방식별 주의 규칙

| 보고서 수량 | 반드시 확인할 것 | 금지되는 단순 대조 |
|---|---|---|
| `sum` | 중복 제거, 필터, 화폐 보정, 기간 합산 범위 | 행 합계와 고유 ID 합계를 같은 값으로 처리 |
| `mean` | 분모, 결측, 가중치, 평균 단위, 그룹 평균 여부 | 전체 평균과 집단 평균의 단순 평균 비교 |
| `weighted_mean` | 가중치 열·버전·정규화 | 가중 평균과 단순 평균 비교 |
| `rate`/`percentage` | 분자, 분모, 비율 단위(% vs %p) | 15명과 15%, 10% 변화와 10%p 변화 비교 |
| `median`/`percentile` | 표본, 보간법, 분위 정의 | 평균·최댓값·다른 분위수 비교 |
| `count` | 관측치/고유 개체/사건 중 무엇인지 | 중복 행 수와 고유 개인 수 비교 |
| `ratio`/`multiplier` | 분자·분모 방향, 기준군 | 역수 또는 기준군이 다른 비율 비교 |
| 회귀·DID 추정치 | 모형식, 공변량, 고정효과, 표준오차, 표본 | 원시 평균과 계수 비교 |

### 평균의 평균 함정

`(기관 A 평균 + 기관 B 평균) / 2`는 두 기관 표본 수가 다르면 전체 평균과 다르다. `group_by`와 `weight_column`이 정확히 일치하거나, 그룹별 분자·분모가 있어 가중 재구성이 가능할 때만 비교한다. 그렇지 않으면 `needs_human_review`이다.

## 6. 자동 복구 탐색: `not_comparable` 뒤에 멈추지 않는다

`not_comparable`은 최초 연결 후보가 같은 수량이 아니라는 판정이다. 이것이 곧 문서 Claim 전체를 포기해야 한다는 뜻은 아니다. 시스템은 최초 후보의 불일치 근거를 보존한 뒤, **같은 Claim에 대한 대체 Provenance 후보**를 제한적으로 재탐색한다.

```text
Claim "서울 응답자 평균 15점"
  ↔ 최초 후보 "sum(score)=15" → not_comparable (기록 유지)
  ↓ 자동 복구 탐색
  ├─ 코드/출력의 mean(score), avg_score, /metrics/seoul_mean 후보 탐색
  ├─ 동일 입력·필터·기간·결측·가중치 근거 대조
  └─ 모두 exact인 직접 출력 후보 발견
       → 새 후보로 의미 계약 대조와 값 비교 재시도
```

### 6-1. 허용되는 자동 복구

| 복구 종류 | 자동화 행동 | 최종 처리 |
|---|---|---|
| 직접 대체 출력 발견 | 동일 승인 실행의 다른 출력 locator·코드 줄에서 같은 의미의 수치 후보 탐색 | 의미 계약·연결 신뢰도가 모두 통과하면 자동 재판정 가능 |
| 표현 정규화 | ms↔s, 원↔백만원, 소수↔%, `%`↔`%p` 등 명시된 변환 적용 | 기존 비교 단계에서 자동 처리 |
| 근거 보강 | 보고서 표 각주·같은 문단, 코드의 인접 필터·가중치·결측 처리에서 `unknown` 필드 근거 추출 | 보강 후 다시 의미 계약 대조; 여전히 unknown이면 검토 큐 |
| 안전한 산술 재구성 | 같은 실행의 명시적 `sum`과 `valid_count` 등으로 평균/비율을 재계산 | `derived_provenance`로 표시하고 `needs_human_review`; 원본 직접 재현 `match`로 승격 금지 |

### 6-2. 자동 복구 금지 사항

- 최초 후보의 `not_comparable`을 삭제하거나 `match`로 덮어쓰지 않는다.
- 변수명 `avg`, `total` 또는 값의 근접성만으로 대체 후보를 만들지 않는다.
- 임의 코드를 수정·삽입·재실행하거나, 미승인 명령을 추가 실행하지 않는다.
- 가중치·필터·기간·결측·분자·분모 중 하나라도 다르면 평균/비율을 임의 재구성하지 않는다.
- 자동 재구성값을 원저자 코드의 직접 출력값 또는 원본 재현 결과로 표시하지 않는다.

### 6-3. 복구 이력 계약

결과에는 최초 후보와 복구 시도를 모두 남긴다.

```json
{
  "initial_provenance_id": "prov-sum-015",
  "initial_status": "not_comparable",
  "initial_reason_codes": ["AGGREGATION_OPERATOR_MISMATCH"],
  "recovery": {
    "attempted": true,
    "strategy": "direct_alternative_output_search",
    "searched_code_locations": ["analysis/report.py:70-105"],
    "candidate_provenance_id": "prov-mean-014",
    "outcome": "direct_candidate_found"
  },
  "final_provenance_id": "prov-mean-014",
  "final_status": "match"
}
```

직접 대체 후보가 없으면 최초 `not_comparable` 또는 `needs_human_review`를 최종 상태로 유지한다. 복구 이력은 UI에서 “자동 재탐색 결과”로 보여, 검토자가 어떤 후보가 왜 교체됐는지 확인할 수 있어야 한다.

## 7. 추출·대조 흐름

```text
1. 보고서 Claim에서 수치·단위와 문맥(표 제목·각주·문장)을 추출
2. 수치 의미 계약의 각 필드를 원문 근거와 함께 생성
3. 코드에서 실제 출력 경로뿐 아니라 집계 함수, 입력 열, 필터, 결측·가중치 처리를 추출
4. 데이터 스키마로 열 존재·자료형·코드값을 확인
5. 필드별 exact / mismatch / unknown 판정
6. mismatch → 최초 후보 `not_comparable`, unknown → 최초 후보 `needs_human_review`
7. 최초 후보가 막혔으면 제한된 자동 복구 탐색과 근거 보강 수행
8. 직접 대체 후보의 의미 필드가 모두 exact일 때만 단위 환산·반올림·허용오차로 값 비교
```

코드 변수명(`total`, `avg`)이나 LLM의 추정만으로 집계 방식을 확정하면 안 된다. 실행 코드 줄 범위, 출력 JSON 경로, 보고서 표/각주 위치를 근거로 저장한다.

## 8. UI·결과 계약

결과 행은 숫자만 나열하지 않고 다음을 보여 준다.

1. 보고서 표시값과 원문 위치
2. 보고서 수치 의미: `평균 / 유효응답자 수 / 결측 제외 / 서울 / 2025년`
3. 재실행 원시값·출력 위치와 코드 줄 범위
4. 재실행 수치 의미
5. 필드별 대조표: `exact`, `mismatch`, `unknown`
6. 값 비교를 수행했는지와 수행하지 않았다면 이유
7. 수행한 경우에만 단위 환산값·반올림값·허용오차·차이

`not_comparable` 또는 `needs_human_review`에서는 `numeric_difference`를 `null`로 둔다. 우연히 같은 `15`여도 초록색 일치 배지나 `0` 차이를 표시하지 않는다.

## 9. 최소 테스트 시나리오

1. 동일 평균·동일 분모·동일 필터·동일 결측 처리, 반올림 차이만 존재 → `match`
2. 보고서 평균 15, 실행 합계 15 → `not_comparable`, 값 비교 없음
3. 보고서 15%, 실행 15명 → `not_comparable`
4. 보고서 단순 평균, 실행 가중 평균 → `not_comparable`
5. 보고서 평균의 결측 처리 미기재 → `needs_human_review`
6. 동일 평균이나 보고서 2025년, 실행 2024년 → `not_comparable`
7. 보고서 그룹 평균, 실행 전체 평균이며 그룹 분자·분모 없음 → `needs_human_review`
8. 동일 수량 계약이 모두 `exact`이고 허용오차 초과 → 그때만 `mismatch`
9. 최초 합계 후보는 `not_comparable`이나 같은 승인 실행의 평균 직접 출력 후보를 발견 → 복구 이력 보존 후 새 후보로 재판정
10. 합계와 유효 건수로 평균을 재구성할 수 있으나 직접 코드 출력이 없음 → `derived_provenance` + `needs_human_review`
11. 대체 후보의 필터 또는 가중치가 다름 → 자동 복구 금지, 최초 결과 유지

## 10. 발표용 한 문장

> 숫자내력은 같은 숫자인지를 먼저 묻지 않고, 그 숫자가 같은 집계·대상·분모·산식에서 나온 값인지를 먼저 검증합니다.
