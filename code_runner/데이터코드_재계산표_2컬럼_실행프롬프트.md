# NAIS 데이터·코드 재계산표 앱 실행 프롬프트

## 목적

이 문서는 보고서와 비교하지 않고, 원본 데이터와 분석 코드만 실행해 재계산 지표를 만드는 앱용 하위 프롬프트다.

최종 웹 표시표는 정확히 두 컬럼만 가진다.

```text
지표 | 재계산값
```

전체 시스템의 보고서 파싱·표 비교·`match/mismatch` 기준은 [NAIS_LINK_코드러너_최종통합마스터프롬프트.md](../code_runner/NAIS_LINK_코드러너_최종통합마스터프롬프트.md)의 책임이다. 이 문서는 그 이전 단계인 데이터·코드 재계산과 웹 표시만 담당한다.

## 1. 입력과 금지 범위

입력은 다음 두 가지다.

1. 분석 데이터
2. 승인된 분석 코드와 실행 계약

이 문서는 다음을 입력으로 사용하지 않는다.

- 연구보고서·논문
- 보고서에 적힌 원 수치
- 표 1 또는 보고서 Claim
- 보고서 위치·페이지·표 번호
- 보고서와의 join·비교·허용오차 판정

질문은 다음 하나다.

```text
이 데이터와 이 코드가 실제 실행에서 생성한 지표와 값은 무엇인가?
```

## 2. 코드 인덱스와 Provenance

실행 전에 코드 인덱스를 만든다.

```text
입력 파일
  → 입력 열·필터·전처리
  → 함수·대입·집계·통계식
  → 출력 변수
  → 출력 파일·JSON key·stdout
```

1차로 `rg`를 사용해 입력 파일명, reader, 집계 함수, 출력 함수를 찾는다.

```bash
rg -n --hidden \
  -e 'read_csv|read\.csv|read_excel|json\.load|fopen|ifstream' \
  -e 'groupby|aggregate|mean|median|sum|count|ratio|correlation|alpha|kappa' \
  -e 'to_csv|to_json|write|save|export|print' \
  code/ analysis/ src/ R/ scripts/
```

가능하면 승인된 Tree-sitter 또는 언어별 parser로 함수·대입·호출·입력·출력 위치를 구조화한다. parser가 없거나 실패하면 `parser_status`를 manifest에 기록하고 자동 확정하지 않는다.

각 지표의 상세 결과에는 다음을 남긴다.

```json
{
  "metric_id": "lyrics.avg_eng_ratio",
  "source_language": "python",
  "source_locations": [
    {
      "path": "scripts/lyrics_analysis.py",
      "line_start": 285,
      "line_end": 307,
      "symbol": "compute_yearly_summary"
    }
  ],
  "output_locator": "output/analysis_tables/lyrics_yearly_summary.csv",
  "input_references": ["datasets/lyrics_metrics.csv"]
}
```

## 3. 입력 데이터 검증

각 입력 파일에 대해 다음을 기록한다.

- 상대 경로
- `input_role`: `raw_input`, `processed_input`, `precomputed_output`
- 형식
- SHA-256
- 행·열 수
- 열 이름·자료형
- 필수 열
- 코드 선언 입력과 실행 중 실제 관찰된 입력

`processed_input`은 원자료가 아니라 이미 가공된 입력임을 표시한다. 기존 결과표를 입력으로 다시 읽어 만든 값은 `precomputed_output`으로 분류하며 원본 재계산으로 부르지 않는다.

다음이 모두 확인되어야 해당 지표의 값을 공식 또는 참고 실행값으로 채운다.

```text
declared_inputs == observed_inputs
입력 SHA-256 일치
필수 열 존재
실행 중 실제 파일 접근 확인
계산식이 입력 열을 참조
```

## 4. 하드코딩과 출력 검증

다음은 재계산으로 인정하지 않는다.

```python
result = 58.27
```

```r
reported_value <- 58.27
```

요약 행·분자·분모·표본 수·통계량을 코드에 직접 입력하고 원본 데이터를 사용하지 않는 경우 `CODE_DATA_INPUT_MISMATCH`를 기록한다.

실행 결과는 실행 전후 파일 목록과 해시를 비교한다.

```text
실행 전 output snapshot
  → 코드 실행
  → 실행 후 output snapshot
  → 새로 생성되거나 변경된 출력만 수집
```

실행 전에 이미 존재하던 CSV·JSON을 코드가 새로 생성한 결과로 착각하지 않는다.

## 5. 실행 모드

### 공식 실행

Docker에서 승인된 entrypoint와 고정 argv로 실행한다.

- 네트워크 차단
- 입력 read-only mount
- 출력 폴더만 write 허용
- CPU·메모리·시간 제한
- 고정 runtime·dependency·locale·timezone·seed
- 코드 revision·image digest·artifact hash 기록

Docker가 없으면 공식 `recomputed`로 표시하지 않는다.

### 로컬 참고 실행

개발·테스트에서는 `reference_local` 모드를 사용할 수 있다.

- 임시 작업 폴더에서 실행
- 원본 출력 파일을 덮어쓰지 않음
- `reference_only=true`
- `official=false`
- 웹 화면에 로컬 참고값임을 표시

## 6. 지표 ID와 그룹 조건

지표명만으로 지표를 식별하지 않는다. 각 상세 기록에는 다음을 둔다.

```json
{
  "metric_id": "lyrics.avg_eng_ratio",
  "metric_name": "평균 영문 문자 비율",
  "group": {"Year": 2025},
  "unit": "%",
  "value_type": "number"
}
```

그룹 식별 열은 지표 표시명에 결합한다.

```text
metric_id: lyrics.avg_eng_ratio
지표: 2025 · 평균 영문 문자 비율
```

그룹 열을 임의로 추정할 수 없으면 `group_inference_failed`를 기록하고 해당 값은 사람 검토 대상으로 둔다.

## 7. 숫자형 정규화

CSV·JSON에서 읽은 숫자 문자열은 표시 전에 숫자로 변환한다.

```text
"58.27" → 58.27
"1,255,014" → 1255014
"42.3%" → 42.3, unit="%"
"N/A" → null
```

JSON의 `재계산값`에는 숫자·문자열·null을 허용하되, 숫자로 해석 가능한 값은 반드시 JSON number로 저장한다. 변환 실패 시 원문을 버리지 말고 상세 manifest에 기록한다.

## 8. 웹 표시용 결과 계약

웹 표시용 `data_code_table.json`의 행은 아래 두 키만 가진다.

```json
{
  "schema_version": "nais-data-code-recalculation-v1",
  "sample_id": "sample-12",
  "execution_mode": "reference_local",
  "reference_only": true,
  "rows": [
    {"지표": "2015 · 총 곡수", "재계산값": 36},
    {"지표": "2015 · 평균 영문 문자 비율", "재계산값": 25.77},
    {"지표": "2025 · 평균 영문 문자 비율", "재계산값": 58.27}
  ]
}
```

`rows`의 각 객체에는 `지표`와 `재계산값` 외의 키를 넣지 않는다. 웹 화면에는 행 인덱스를 표시하지 않는다.

## 9. 비교용 상세 결과 계약

나중에 다른 프롬프트가 추출한 보고서 수치와 연결할 수 있도록, 웹 표시 JSON과 별도로 `recalculation_records.json`을 저장한다.

```json
{
  "schema_version": "nais-recalculation-records-v1",
  "sample_id": "sample-12",
  "records": [
    {
      "metric_id": "lyrics.avg_eng_ratio",
      "metric_name": "평균 영문 문자 비율",
      "group": {"Year": 2025},
      "display_label": "2025 · 평균 영문 문자 비율",
      "value": 58.27,
      "unit": "%",
      "value_type": "number",
      "input_files": [
        {
          "path": "datasets/lyrics_metrics.csv",
          "input_role": "processed_input",
          "sha256": "sha256:..."
        }
      ],
      "code_provenance": {
        "source_language": "python",
        "source_locations": [
          {"path": "scripts/lyrics_analysis.py", "line_start": 285, "line_end": 307}
        ],
        "output_locator": "output/analysis_tables/lyrics_yearly_summary.csv"
      },
      "run_status": "reference_only",
      "reason_codes": ["REFERENCE_VALUE_NOT_OFFICIAL"]
    }
  ]
}
```

비교용 상세 결과는 웹의 두 컬럼 표에 표시하지 않는다. 보고서 비교 단계가 이 파일을 읽는다.

## 10. 실패 처리

실패한 지표도 삭제하지 않는다.

```text
코드가 입력을 읽지 않음
  → value = null
  → run_status = analysis_failed
  → CODE_DATA_INPUT_MISMATCH

코드 출력 경로·계산 경로 없음
  → value = null
  → run_status = no_provenance_candidate

실행 오류·패키지 누락·출력 누락
  → value = null
  → run_status = execution_failed

Docker 없음
  → 공식 실행 시작 금지
  → run_status = isolation_unavailable

로컬 참고 실행 성공
  → value 기록 가능
  → run_status = reference_only
  → official = false
```

표시표는 실패 행도 `지표 | null`로 유지하고, 실패 사유는 `recalculation_records.json`과 실행 manifest에 둔다.

## 11. 완료 조건

1. 보고서 없이 데이터와 코드만 사용했다.
2. 코드 인덱스에서 입력·계산·출력 경로를 확인했다.
3. 실제 입력 파일 접근과 해시를 확인했다.
4. 실행 전후 출력 파일을 비교해 실제 생성 결과만 수집했다.
5. 모든 결과값을 숫자형으로 정규화했다.
6. 각 상세 결과에 `metric_id`와 그룹 조건이 있다.
7. 웹 표시 JSON의 행은 정확히 `지표`, `재계산값` 두 키만 가진다.
8. 비교용 상세 결과와 웹 표시 결과를 분리했다.
9. 공식 Docker 실행과 로컬 참고 실행을 구분했다.
10. 보고서 수치와의 비교·join·`match/mismatch`는 수행하지 않았다.
