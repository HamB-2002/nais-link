# NAIS 정거장 1·2 실행 프롬프트

## 목적

이 문서는 NAIS 숫자내력의 앞단 두 정거장을 수행한다.

```text
보고서 원문·구조화 artifact
  → 1 정거장: 검증 대상 수치 수집
  → 2 정거장: 그 수치를 만든 코드·데이터·계산 경로 추적
  → 3컬럼 검토표
```

최종 사람이 보는 표는 반드시 아래 세 컬럼만 가진다.

```text
보고서 내 수치 | 지표 | 추적한 내력
```

이 문서는 보고서 수치와 재계산값의 `match/mismatch`를 판정하지 않는다. 코드 실행 자체와 재계산 후보 생성은 [데이터코드_재계산표_2컬럼_실행프롬프트.md](./데이터코드_재계산표_2컬럼_실행프롬프트.md)의 실행 계약을 따르고, 최종 표 대조는 [NAIS_LINK_코드러너_최종통합마스터프롬프트.md](./NAIS_LINK_코드러너_최종통합마스터프롬프트.md)의 기준을 따른다.

## 1. 입력 범위

입력은 다음 세 가지다.

1. 연구보고서·논문 원문 또는 보고서 파서가 만든 구조화 artifact
2. 분석에 사용된 원본·전처리 데이터와 입력 manifest
3. 분석 코드, 실행 계약, 의존성·빌드 설정

보고서만 보고 코드 위치를 꾸며내지 않는다. 데이터와 코드만 보고 보고서의 수치를 만들어내지도 않는다. 보고서 위치와 코드 위치는 각각의 원본 근거를 보존한 상태에서 연결 후보로 만든다.

## 2. 작업 경계

이 프롬프트가 하는 일:

- 보고서에서 검증 대상 숫자 후보를 수집한다.
- 검증 대상이 아닌 숫자를 규칙에 따라 제외한다.
- 수치의 기간·모집단·분모·단위·계산 의미를 추출한다.
- 데이터·분석 코드에서 해당 의미를 표현하는 코드 후보를 찾는다.
- 입력 reader, 계산식, 출력 변수·파일·key, 코드 줄 번호를 기록한다.
- 연결 성공·불확실·실패를 표에 보존한다.

이 프롬프트가 하지 않는 일:

- 코드를 공식 재실행하거나 Docker 실행 성공을 가장하지 않는다.
- 보고서 값과 재계산값의 `match/mismatch`를 판정하지 않는다.
- 숫자 값만 같다는 이유로 코드와 보고서를 연결하지 않는다.
- 표 1·표 2의 full outer join, 허용오차, 단위 환산 판정을 수행하지 않는다.

## 3. 1 정거장 — 보고서 수치 수집

### 3-0. 사전 숫자 게이트 — 표를 만들기 전에 먼저 거른다

보고서의 모든 숫자를 후보 표에 넣지 않는다. 수집은 다음 두 단계로 나눈다.

```text
1차: 정규식·토큰 검색으로 숫자 후보를 빠르게 발견
  → 2차: 주변 문맥·문서 구조·숫자 유형 규칙으로 검증 대상 여부 판정
  → 대상만 1정거장 표 후보로 전달
  → 애매한 것은 삭제하지 않고 사람 검토 큐로 보존
```

1차 검색은 넓게 하되, 2차 판정 전에 다음 사전 제외 규칙을 적용한다.

| 분류 | 예시 | 기본 처리 |
|---|---|---|
| 날짜·연도 | `2026년 5월`, `2015–2025`, `2024.03.01` | 검증 수치에서 제외하고 `period` 문맥으로만 보존 |
| 문서 구조 번호 | `3.2절`, `표 4`, `Figure 2`, `부록 1` | 제외하고 위치 metadata로만 보존 |
| 위치·주석 번호 | 쪽번호, 각주번호, 표 셀 번호 | 제외하고 locator로만 보존 |
| 식별자 | 전화번호, 사업자번호, 우편번호, 연구과제번호 | 제외 |
| 법령·인용 | `제5조 제2항`, `(홍길동, 2016)` | 제외 |
| 파일·버전 metadata | `v2.1`, `2026-09-30`, 접근일 | 제외 |
| 계산 설명용 숫자 | `N=62`, `분모 100`, `5점 척도` | 결과값이 아니면 제외하고 의미 evidence로 보존 |

다음 신호가 숫자 주변 문장·표 머리글·행/열 레이블에 있으면 검증 후보로 올린다.

- `%`, `%p`, `퍼센트`, `비율`, `증가율`, `감소율`
- `배`, `배수`, `평균`, `중앙값`, `최대`, `최소`, `합계`, `개`, `건`, `명`, `원`
- `상관`, `회귀`, `계수`, `효과크기`, `통계량`, `자유도`, `p값`, `신뢰구간`
- `총`, `비중`, `분포`, `점수`, `차이`, `변화량`, `표준편차`, `분산`
- 표·그림 안에서 수치 열 또는 결과 행으로 반복되는 숫자

숫자만 있고 위 신호가 없다고 즉시 버리지 않는다. 다음 조건이면 `needs_human_review` 후보로 남긴다.

- 본문이 결과를 보고하는 문장인데 지표명이 생략된 경우
- `N=62`처럼 표본 수가 실제 검증 대상인지 설명용인지 불명확한 경우
- 연도 자체가 아니라 `2015년 평균 36건`처럼 결과값의 그룹 조건과 함께 나타난 경우
- 표의 숫자 열 제목을 파서가 복원하지 못한 경우

사전 게이트는 숫자를 정규화하거나 코드와 연결하지 않는다. 이 단계의 출력은 아래 세 가지다.

```text
target_candidate       → 1정거장 수치 수집으로 전달
non_target_number      → 표 후보에서 제외, 제외 사유·원문 위치만 audit log에 기록
needs_human_review     → 후보 표에 포함하되 자동 코드 추적 확정 금지
```

문서별로 `전체 숫자 토큰 수`, `사전 제외 수`, `검증 후보 수`, `사람 검토 수`를 manifest에 기록한다. 제외된 숫자를 최종 표에 다시 넣어 처리 시간을 늘리지 않는다.

### 3-1. 수집 위치

본문 문장, 표 셀, 표 제목·각주, 그림 캡션·본문 설명, 부록에서 숫자를 수집한다. 위치는 최소 다음을 포함한다.

```json
{
  "source_anchor": "report.hwpx#page=12&table=Table 3&cell=r4c2",
  "page": 12,
  "section": "4.2 분석 결과",
  "table_id": "Table 3",
  "row": "평균 만족도",
  "column": "전체",
  "quote": "전체 평균 만족도는 42.3%였다."
}
```

페이지·표·행·열을 확인할 수 없으면 비워 두고 `LOCATION_UNCERTAIN`을 기록한다. 임의의 페이지나 셀을 만들지 않는다.

### 3-2. 검증 대상으로 수집하는 숫자

- 비율·백분율·퍼센트포인트
- 배수·증가율·감소율
- 금액·평균·중앙값·합계·개수
- 최솟값·최댓값·분산·표준편차
- 상관계수·회귀계수·효과크기
- 검정통계량·자유도·p값·신뢰구간
- 표·그림에 표시된 그룹별·기간별 결과값

문자열 원문을 먼저 보존하고, 비교용 숫자 정규화는 별도 필드에 둔다. `42.3%`, `42.3`, `p < .01`, `2.7배` 같은 표기를 원문 그대로 잃지 않는다.

### 3-3. 수집하지 않는 숫자

사전 숫자 게이트에서 `non_target_number`로 판정된 숫자는 기본적으로 검증 대상에서 제외한다.

- 날짜·연도·기간 표기: `2026년 5월`, `2015–2025`
- 항목·절·표 번호: `3.2절`, `표 4`, `Figure 2`
- 폭번호·각주번호·문헌 인용 연도
- 전화번호·사업자번호·우편번호·식별자
- 법령 조항·페이지 번호·파일 버전·접근일
- 표본 수나 분모처럼 지표 계산 의미를 설명하는 숫자 자체
- 코드·로그·각주에만 있고 보고서 결과를 주장하지 않는 숫자

단, 위 숫자가 보고서에서 분석 결과로 명시되면 제외하지 말고 `needs_human_review`와 포함 근거를 기록한다. 예를 들어 `N=62`가 단순 표본 설명인지, 검증할 표본 수 결과인지 문맥으로 확정할 수 없으면 자동 확정하지 않는다. 연도·날짜가 결과의 그룹 조건으로 쓰인 경우에는 수치에서 제거하되 `period` 의미 evidence로 연결한다.

### 3-4. 수치 후보 의미 필드

각 후보는 다음 의미 evidence를 가진다.

```text
metric, aggregation_or_formula, period, population, denominator,
filters, missing_value_policy, weight, transformation, unit
```

각 항목은 단순 추정 문자열이 아니라 다음 구조를 사용한다.

```json
{
  "raw_value": "42.3%",
  "normalized_value": 42.3,
  "state": "exact_candidate",
  "locator": "report.hwpx#page=12&table=Table 3&cell=r4c2",
  "extraction_method": "table_cell_and_caption",
  "reason_code": null
}
```

확인하지 못한 의미는 `unknown`으로 남기고 `METRIC_MEANING_UNCERTAIN`, `PERIOD_NOT_FOUND`, `DENOMINATOR_NOT_FOUND` 같은 구체적인 reason code를 기록한다.

## 4. 2 정거장 — 코드 내력 추적

### 4-1. 코드 인덱스 생성

코드를 다음 그래프로 인덱싱한다.

```text
보고서 수치의 의미·표현
  → 검색 단서 후보
  → 입력 파일·입력 열
  → reader·필터·전처리
  → 함수·대입·집계·통계식
  → 지표 변수·그룹 변수
  → 출력 파일·JSON key·stdout·그림 원자료
```

1차 검색에는 `rg`를 사용한다.

```bash
rg -n --hidden \
  -e '42\\.3|42,3|read_csv|read\\.csv|read_excel|json\\.load|fopen|ifstream' \
  -e 'mean|median|sum|count|ratio|correlation|kappa|p_value|groupby|aggregate' \
  -e 'to_csv|to_json|write|save|export|print' \
  data/ code/ analysis/ src/ R/ scripts/
```

보고서 숫자의 표기 변형(천 단위 쉼표, `%`, 소수 자릿수, `p < .01`)과 지표·행·열 의미 단어를 함께 검색한다. 숫자 literal 검색만으로 연결을 확정하지 않는다.

가능하면 Tree-sitter 또는 언어별 parser로 함수·대입·호출·입력·출력 위치를 구조화한다. parser가 없거나 데이터 흐름이 끊기면 `parser_status`와 탐색 범위를 기록하고 자동 확정하지 않는다.

### 4-2. 언어 중립 추적

확장자와 프로젝트 설정을 기준으로 Python, R, C/C++, Java, Julia, MATLAB, Stata, SAS, SQL, Rust, Go, 셸 및 노트북을 식별한다. 언어별 구문을 공통 의미로 변환하되, 공통 결과에는 다음만 의존한다.

- 입력 reader와 입력 파일·열
- 필터·전처리·변환
- 집계·통계식·분모
- 출력 변수·파일·key
- 소스 파일·줄 범위·함수/심볼

실행 진입점이나 의존성을 찾지 못해도 코드 위치 후보와 실패 사유는 남긴다. 언어를 이유로 코드 추적을 생략하지 않는다.

### 4-3. 코드 후보 판정 규칙

다음 근거를 모두 또는 일부 조합해 후보를 평가한다.

1. 보고서 지표 의미와 코드 계산식의 의미가 연결되는가.
2. 보고서 기간·모집단·분모·필터가 코드와 연결되는가.
3. 코드가 분석 데이터를 실제로 읽는가.
4. 코드 계산 결과가 출력 파일·변수·key로 이어지는가.
5. 코드 위치와 출력 위치를 재현 가능한 locator로 기록할 수 있는가.

다음은 공식 내력으로 인정하지 않는다.

```python
reported_value = 42.3
```

```r
summary <- 42.3
```

보고서 숫자와 같은 숫자가 코드에 literal로 있지만 입력 데이터·계산식·출력 연결이 없으면 `HARDCODED_VALUE_NOT_LINEAGE`다. 기존 결과 CSV를 읽어 다시 출력한 경우 `precomputed_output`으로 표시한다.

### 4-4. 후보가 여러 개인 경우

후보를 하나로 임의 선택하지 않는다. 모든 후보에 대해 다음을 기록한다.

- 후보 code locator
- 입력·계산·출력 연결
- 의미 기준별 상태
- 선택·탈락 사유
- 불확실성·충돌 reason code

후보가 여러 개이고 의미·기간·모집단·분모 중 하나라도 확정되지 않으면 `needs_human_review`다.

## 5. 세 컬럼 최종 표 계약

웹 또는 사람이 보는 최종 표는 행마다 정확히 아래 세 키만 가진다.

```json
{
  "보고서 내 수치": "42.3%",
  "지표": "전체 평균 만족도",
  "추적한 내력": "추적 후보: analysis/main.R:81-87 → read_csv(data/survey.csv) → mean(score) → outputs/summary.csv#/전체/평균; 상태=후보확인"
}
```

### 5-1. 컬럼 작성 규칙

`보고서 내 수치`:

- 보고서에 표시된 원문 수치를 그대로 쓴다.
- 정규화 값이나 재계산 값을 이 컬럼에 덮어쓰지 않는다.
- 동일 수치가 여러 위치에 있으면 위치별 행을 보존한다.

`지표`:

- 보고서 문맥으로 확인된 지표명을 사용한다.
- 보고서 표현과 코드 표현이 다르면 보고서 지표명 뒤에 코드 명칭을 괄호로 덧붙일 수 있다.
- 의미가 확인되지 않으면 `미확정 지표`로 쓰고 상세 artifact에 `METRIC_MEANING_UNCERTAIN`을 남긴다.
- 값이 같다는 이유로 지표명을 추정하지 않는다.

`추적한 내력`:

- 사람이 읽을 수 있는 한 줄 요약으로 만든다.
- 최소 `상태`, 코드 파일·줄 번호, 입력 데이터, 계산 경로, 출력 locator 또는 실패 사유를 포함한다.
- `추적 불가`라고만 쓰지 말고 탐색 범위와 구체적 reason code를 포함한다.

표시 레코드에는 세 키 이외의 키를 넣지 않는다. 행 번호·SHA-256·페이지·상세 상태·reason code는 표시 문자열에 필요한 만큼 요약하되, 구조화 artifact에 별도로 보존한다.

## 7. 최종 대조 입력으로의 정규화 handoff

`station12_lineage_records.json`은 사람이 보는 3컬럼 표가 아니라, 최종 대조 엔진으로 넘길 원천 artifact다. 이 파일을 그대로 값 비교에 사용하지 않고 아래 canonical artifact로 정규화한다.

```text
station12_lineage_records.json
  → CanonicalReportTableArtifact
  → CanonicalExecutionTableArtifact 후보
  → NAIS_LINK_코드러너_최종통합마스터프롬프트.md의 대조 엔진
```

### 7-1. 보고서 측 정규화

각 record를 보고서 측 canonical 셀로 변환한다.

| 정거장 record | CanonicalReportTableArtifact |
|---|---|
| `claim_candidate_id` | claim/cell identity |
| `report_locator.source_anchor` | `source_locator` |
| `report_locator.table_id` | `table_id` |
| `report_locator.row`, `column` | `coordinate.row_key`, `column_path` |
| `report_value.raw` | `raw_value` |
| `report_value.normalized` | `value` |
| `semantics` | `SemanticEvidence` 10개 항목 |
| `report_locator.quote` | 원문 근거·normalization evidence |

`report_value.normalized`가 없거나 의미 evidence가 `unknown`이면 canonical 셀을 만들더라도 확정 상태로 올리지 않는다. `evidence_incomplete`와 구체적 reason code를 보존한다.

### 7-2. 실행 측 정규화 후보

정거장 2의 `code_candidates`는 실행 결과가 아니다. 코드·데이터 연결과 출력 locator가 확인된 후보만 `CanonicalExecutionTableArtifact` 후보로 변환한다.

```text
code_candidates[].source_locations → code_locator
code_candidates[].input_references → input evidence
code_candidates[].calculation_path → semantics.aggregation_or_formula
code_candidates[].output_locator → output_locator
code_candidates[].metric_name → semantics.metric
group·period·unit → coordinate와 SemanticEvidence
```

다음 상태는 실행 artifact로 확정하지 않는다.

- `no_provenance_candidate`
- `analysis_failed`
- `HARDCODED_VALUE_NOT_LINEAGE`
- `PRECOMPUTED_OUTPUT_ONLY`
- 출력 locator가 없는 후보

이 후보들은 `candidate_assessments`에 보존하고 `execution_status: not_started` 또는 구체적 실패 상태로 넘긴다. 실제 재실행 결과가 생성되기 전에는 `recomputed`, `match`, `mismatch`를 쓰지 않는다.

### 7-3. 정규화 금지 규칙

- 세 컬럼 표시 문자열을 canonical artifact의 유일한 입력으로 사용하지 않는다.
- 보고서 값과 코드 후보 값이 같다는 이유로 좌표·의미를 채우지 않는다.
- 보고서의 행명·표 번호를 코드의 `coordinate_hint`로 복사하지 않는다.
- 코드 출력의 그룹·열·패널에서 확인되지 않은 coordinate를 임의로 만들지 않는다.
- 승인된 동의어·단위·행/열 매핑이 없으면 `unknown`과 reason code로 보존한다.

정규화 결과에는 원본 artifact 해시, 정규화 정책 버전, mapping registry 버전을 기록한다. 정규화 실패는 수치 `mismatch`가 아니라 `evidence_incomplete`다.

## 8. 상태와 실패 사유

허용 상태는 다음과 같다.

```text
claim_collected
candidate_confirmed
needs_human_review
no_provenance_candidate
analysis_failed
evidence_incomplete
```

실행하지 않았으므로 `recomputed`, `match`, `mismatch`는 이 문서의 상태로 사용하지 않는다.

대표 reason code:

- `NON_TARGET_NUMBER`
- `LOCATION_UNCERTAIN`
- `METRIC_MEANING_UNCERTAIN`
- `PERIOD_NOT_FOUND`
- `POPULATION_NOT_FOUND`
- `DENOMINATOR_NOT_FOUND`
- `CODE_PROVENANCE_NOT_FOUND`
- `CODE_DATA_INPUT_MISMATCH`
- `HARDCODED_VALUE_NOT_LINEAGE`
- `PRECOMPUTED_OUTPUT_ONLY`
- `MULTIPLE_CODE_CANDIDATES`
- `PARSER_OR_INDEXER_UNAVAILABLE`
- `OUTPUT_LOCATOR_NOT_FOUND`

실패와 불확실성도 세 컬럼 표에 행으로 남긴다. 단, 상세 사유는 내부 artifact에 보존한다.

## 8. 완료 조건

1. 보고서의 검증 대상 숫자와 제외된 숫자를 구분했다.
2. 각 수집 숫자에 원문과 `source_anchor`가 있다.
3. 각 수집 숫자에 지표·기간·모집단·분모·단위의 상태가 있다.
4. 코드 후보마다 파일·줄 번호·함수/심볼·입력·계산 경로·출력 위치가 있다.
5. 코드와 데이터 연결이 없는 literal은 공식 내력으로 인정하지 않았다.
6. 후보가 여러 개면 모두 보존하고 사람 검토로 보냈다.
7. 최종 표시표는 `보고서 내 수치`, `지표`, `추적한 내력` 세 컬럼만 가진다.
8. 상세 위치·의미·실패 사유는 `station12_lineage_records.json`에 별도 보존한다.
9. 코드 재실행·재계산·허용오차·`match/mismatch`는 수행하지 않았다.
10. 이후 3정거장이 읽을 수 있도록 report locator와 code/output locator를 잃지 않았다.
