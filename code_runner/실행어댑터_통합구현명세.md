# 숫자내력 `code_runner` 실행 어댑터 통합 구현 명세

> 범위: `code_runner/`만 수정한다.
>
> 목적: 현재의 삼중 대조 판정 엔진에 실제 파일 메타데이터와 안전한 재실행 결과를 공급한다.

---

## 1. 완료 목표

현재 엔진은 이미 아래와 같은 판정을 수행한다.

```text
보고서 ↔ 데이터 의미 조건
코드 ↔ 데이터 입력·스키마·변환 조건
보고서 ↔ 코드 실행값
```

이번 구현은 사람이 만든 `DataFile`, `CodeDataContract`, `Execution` 객체를 신뢰하지 않는다. 업로드·승인된 계약·Docker 실행에서 다음 사실을 직접 수집해 엔진에 전달한다.

```text
업로드 데이터 파일
  → 파일 해시 / CSV 스키마 / 행 수 / 상대 경로
  → DataFile

승인 실행 계약
  → script_id / 허용 명령 / 선언 입력 / 출력 locator / 리소스 제한
  → CodeDataContract의 선언 근거

Docker 격리 실행
  → 격리 입력 스냅샷 목록 / 종료 상태 / 출력 수치 / 실행 근거
  → Execution + CodeDataContract의 입력 근거
```

최종 호출은 아래 하나로 연결한다.

```python
result = run_triple_review(upload_bundle, approved_contract, claim, trace, tolerance)
```

이 함수는 `TripleReviewResult`를 반환하며, 파일·명령·컨테이너 정책이 검증되지 않으면 실행하지 않고 안전한 상태를 반환한다.

## 2. 모듈 경계

| 새 모듈 | 책임 | 금지 사항 |
|---|---|---|
| `file_inspector.py` | 데이터 파일을 읽어 해시·행 수·열 이름·간단 자료형을 추출 | 파일 전체 내용/개인정보를 결과에 저장 |
| `execution_contract.py` | 승인된 script·명령·입력·출력·Docker 정책을 표현 및 검사 | 업로드 문자열을 명령으로 실행 |
| `docker_runner.py` | 고정된 Docker 명령으로 컨테이너 실행하고 결과를 수집 | 로컬 실행 우회, `shell=True`, 네트워크 허용 |
| `adapter.py` | 검사 결과를 `TripleComparisonRequest`로 조립하고 `evaluate_triple` 호출 | 판정 규칙을 복제 |
| `test_*.py` | 파일 검사·계약 거부·실행 결과 변환 테스트 | 실제 민감 데이터·임의 코드 실행 |

기존 `triple_models.py`, `triple_workflow.py`는 판정 책임을 유지한다. 실행 어댑터가 수치 판정을 다시 구현하면 안 된다.

## 3. 입력 계약

### 3-1. 업로드 번들

```python
@dataclass(frozen=True, slots=True)
class UploadBundle:
    data_root: Path
    files: tuple[Path, ...]
```

- `files`는 `data_root` 내부의 일반 파일만 허용한다.
- 절대 경로, `..`, 심볼릭 링크, 디렉터리, 중복 경로는 거부한다.
- MVP 지원 확장자는 `.csv`만이다. 다른 형식은 `evidence_incomplete`와 `UNSUPPORTED_DATA_FORMAT`을 반환한다.
- 파일 최대 크기와 최대 행 수는 계약에 포함하고, 초과 시 읽기를 중단한다.

### 3-2. 승인 실행 계약

```yaml
script_id: benchmark_v1
image: nais-link-runner:locked
command: ["python", "/workspace/analysis/run.py", "--input", "/input/benchmark.csv"]
declared_inputs:
  - path: data/benchmark.csv
    sha256: "..."
output:
  path: /output/result.json
  locator: /speedup
  unit: 배
limits:
  timeout_seconds: 300
  memory: 4g
  cpus: "1"
```

계약은 서버/팀 allowlist에서만 선택한다. 업로드 요청의 `command`, `image`, `script_path`, `output_path`는 신뢰하지 않고 계약을 대체할 수 없다.

### 3-3. 실행 관찰 기록

실행 후 남기는 관찰값은 최소한 다음뿐이다.

```json
{
  "run_id": "uuid",
  "image_digest": "sha256:...",
  "exit_code": 0,
  "duration_seconds": 3.2,
  "observed_input_digests": ["sha256:..."],
  "output_sha256": "sha256:...",
  "output_locator": "/speedup"
}
```

표준 출력·표준 오류는 길이를 제한하고 비밀값을 마스킹한다. 원문 데이터, 보고서 전체 내용, 환경 변수, 토큰은 저장하거나 반환하지 않는다.

## 4. 파일 검사기 동작

### 4-1. `inspect_csv(path)`

1. 경로가 업로드 루트 내부의 정규 파일인지 확인한다.
2. 바이너리 스트리밍으로 SHA-256을 계산한다. 전체 파일을 메모리에 올리지 않는다.
3. `csv` 표준 라이브러리로 UTF-8 CSV 헤더와 행 수를 읽는다.
4. 첫 N개 값만 이용해 각 열을 `integer`, `decimal`, `string`, `empty` 중 하나로 추정한다.
5. `DataFile(path, sha256, row_count, columns)`를 만든다.

중단 조건:

| 조건 | 상태 | reason code |
|---|---|---|
| 파일 없음/루트 탈출/심볼릭 링크 | `evidence_incomplete` | `DATA_PATH_REJECTED` |
| CSV 외 확장자 | `evidence_incomplete` | `UNSUPPORTED_DATA_FORMAT` |
| 헤더 없음/중복 열 | `evidence_incomplete` | `DATA_SCHEMA_INVALID` |
| UTF-8·CSV 파싱 오류 | `evidence_incomplete` | `DATA_PARSE_FAILED` |
| 크기/행 제한 초과 | `evidence_incomplete` | `DATA_LIMIT_EXCEEDED` |

해시는 `hashlib.sha256`, CSV는 `csv`를 사용한다. 이 단계에 외부 라이브러리를 추가하지 않는다.

### 4-2. 검사와 실행 사이의 변조 방지

검사한 원본 경로를 그대로 컨테이너에 bind mount하면, 검사 후 다른 프로세스가 파일을 바꾸는 TOCTOU 문제가 생긴다. 따라서 다음 순서를 고정한다.

```text
업로드 원본 검사
  → 실행 전용 임시 디렉터리에 파일별 안전 복사
  → 복사본 SHA-256 재계산
  → 계약 해시와 복사본 해시 일치 확인
  → 복사본만 read-only로 컨테이너에 mount
  → 실행 후 복사본 SHA-256 재확인
```

- 원본 업로드 경로와 컨테이너 입력 경로를 동일시하지 않는다.
- 임시 디렉터리는 run_id별로 새로 만들고, 실행이 끝나면 정리한다.
- 입력 복사본 해시가 실행 전후 달라지면 결과는 폐기하고 `INPUT_SNAPSHOT_CHANGED`로 처리한다.
- 코드도 승인된 revision을 별도 read-only 작업 디렉터리로 준비해, 업로드 경로의 최신 파일을 직접 실행하지 않는다.

## 5. Docker 실행 정책

Docker를 쓸 수 없으면 무조건 `isolation_unavailable`이다. `subprocess`로 Python/R/Stata를 호스트에서 직접 실행하는 대체 경로는 금지한다.

허용되는 Docker 실행 정책:

```text
docker run --rm
  --network none
  --read-only
  --user <non-root uid:gid>
  --cap-drop ALL
  --security-opt no-new-privileges
  --pids-limit <계약값>
  --memory <계약값>
  --cpus <계약값>
  --tmpfs /tmp:rw,noexec,nosuid,size=64m
  --mount type=bind,src=<검증된 코드>,dst=/workspace,readonly
  --mount type=bind,src=<검증된 데이터>,dst=/input,readonly
  --mount type=bind,src=<새 출력 디렉터리>,dst=/output
  <allowlist image digest>
  <고정된 command 배열>
```

필수 규칙:

- `subprocess.run([...], shell=False, timeout=...)`만 사용한다.
- 이미지 태그가 아니라 digest로 승인한다.
- `--privileged`, host network, host PID/IPC, Docker socket, host device mount를 사용하지 않는다.
- 컨테이너 프로세스는 non-root user로 실행하며, 계약의 image가 해당 user를 지원하지 않으면 실행 계약 자체를 승인하지 않는다.
- 명령 배열은 계약에 저장된 값과 완전히 동일해야 한다.
- 코드·입력은 읽기 전용, 출력 임시 디렉터리만 쓰기 가능하다.
- 컨테이너가 종료되거나 시간 초과되어도 호스트 파일을 수정하지 않는다.
- 실행 시작 전 Docker CLI와 이미지 digest를 확인한다.
- `docker` 명령 부재/daemon 오류는 `isolation_unavailable`, 종료 코드 비정상/시간 초과/출력 없음은 `execution_failed`다.

### 실행 신뢰 경계

Docker는 **팀 allowlist로 승인한 분석 코드**의 격리 수단이다. 공개 업로드의 임의 코드·Dockerfile·컨테이너 image를 실행하는 보안 경계가 아니다. Docker daemon 권한은 호스트에 강하므로, 운영 환경에서는 전용 실행 워커와 승인 image registry를 사용한다. 이 MVP는 임의 코드 실행 기능을 추가하지 않는다.

### 입력 관찰의 한계

컨테이너 내부에서 실제 파일 open을 정확히 관찰하려면 런타임 계측이 필요하다. MVP는 **컨테이너에 mount한 입력 스냅샷의 해시 + 계약의 declared_inputs**만 기록한다. 결과 JSON/UI에서 이를 `mounted_inputs`로 표시하며, `observed_inputs` 또는 “실제 open 확인”이라고 과장하지 않는다. 임의 경로 접근은 마운트 자체가 막는다.

향후 확장 시에는 Python `sitecustomize`/eBPF 등 언어·환경별 계측을 별도 작업으로 넣으며, 계측 근거가 없을 때 실제 open을 확인한 것처럼 표시하지 않는다.

## 6. 출력 수치 추출과 삼중 대조 연결

1. Docker 성공 후 계약의 `/output/result.json`만 읽는다.
2. JSON locator는 JSON Pointer 형식(`/speedup`)만 지원한다. 점 표기·임의 표현식·JSONPath는 금지한다.
3. locator 값은 유한한 decimal 숫자여야 한다. 문자열·NaN·Infinity·배열·객체는 `OUTPUT_VALUE_INVALID`다.
4. 계약의 unit으로 `NumericValue`를 만든다.
5. 데이터 검사 결과와 실행 결과를 `TripleComparisonRequest`로 조립한다.
6. `evaluate_triple`을 한 번 호출하고 결과를 그대로 반환한다.

출력 파일도 신뢰 경계다.

- `/output/result.json`은 최대 크기를 제한하고, 단일 JSON 문서만 허용한다.
- duplicate key가 있는 JSON은 거부한다.
- JSON Pointer의 `~0`, `~1` escape 규칙만 지원하고, 배열 인덱스·음수 인덱스·와일드카드는 지원하지 않는다.
- 출력 파일 hash, image digest, 승인 script revision, input snapshot digest, 정책 버전을 결과의 감사 메타데이터로 남긴다.
- stdout/stderr는 오류 원인 확인용으로 제한 길이·마스킹 후 보관하며, 결과 수치의 근거로 사용하지 않는다.

### 재현성 환경 고정

실행 계약에는 `image_digest`, `script_revision`, `input_snapshot_digest`, `policy_version`을 필수로 둔다. 분석 코드가 난수·시간·locale에 의존한다면 계약에는 seed, timezone, locale도 포함해야 한다. 이 값이 없으면 원본 재현이 아니라 `needs_human_review`로 표시한다.

상태 우선순위:

```text
업로드/계약 검증 실패
  → evidence_incomplete
Docker 격리 불가
  → isolation_unavailable
컨테이너 실행/출력 추출 실패
  → execution_failed
보고서↔데이터 또는 코드↔데이터 불일치
  → not_comparable / evidence_incomplete / needs_human_review
모든 근거 통과 후 수치 비교
  → match / mismatch
```

## 7. 필수 테스트

모든 테스트는 임시 디렉터리와 작은 fixture를 사용한다. 실제 Docker 의존 테스트는 Docker가 있는 환경에서만 별도 marker로 실행한다.

1. 같은 CSV는 동일 SHA-256·행 수·열 목록을 만든다.
2. 루트 탈출·심볼릭 링크·지원하지 않는 확장자를 거부한다.
3. 계약과 업로드 파일 해시가 다르면 컨테이너 실행 전에 `CODE_DATA_INPUT_MISMATCH`가 된다.
4. 승인되지 않은 script_id·이미지 digest·명령 배열을 거부한다.
5. Docker가 없을 때 호스트 실행 없이 `isolation_unavailable`을 반환한다.
6. timeout·비정상 종료·출력 파일 없음·잘못된 JSON·잘못된 locator는 `execution_failed`가 된다.
7. 정상 출력 `1.2초`가 보고서 `1200ms`와 대조돼 `match`가 된다.
8. 컨테이너 실행 전후 입력 파일 SHA-256이 같은지 확인한다.
9. 입력 원본을 검사한 뒤 바꿔도 컨테이너가 복사본 스냅샷만 읽는지 확인한다.
10. duplicate key JSON, JSON Pointer escape, oversized output을 안전하게 거부한다.
11. non-root, network none, read-only mount 등 Docker 정책 인자가 빠지면 실행 계약 검증에서 거부한다.
12. image digest·script revision·input snapshot digest·policy version이 감사 메타데이터에 남는지 확인한다.

## 8. 완료 정의

아래가 모두 충족되면 `code_runner` 실행 어댑터 MVP 완료다.

- 실제 CSV에서 `DataFile`을 생성한다.
- 승인 계약 밖의 코드·명령·이미지는 실행할 수 없다.
- Docker 정책 검증 실패 시 호스트 실행으로 우회하지 않는다.
- 출력값은 고정된 JSON Pointer로만 읽는다.
- 검사본과 실행 입력이 같은 immutable snapshot임을 증명한다.
- `mounted_inputs`와 런타임 파일 open 관찰을 혼동하지 않는다.
- 출력·실행·환경 근거를 재현 가능한 감사 메타데이터로 남긴다.
- 기존 `evaluate_triple`가 모든 판정의 단일 소스다.
- 파일/계약/격리/실행/대조 실패가 서로 다른 reason code로 화면에 전달된다.
- 테스트·린트·타입 검사가 통과한다.
