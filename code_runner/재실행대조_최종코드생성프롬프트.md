# 숫자내력 `code_runner` 최종 코드생성 프롬프트

> 사용법: 아래 **프롬프트 전체**를 Codex·Claude Code·Cursor 같은 코드 생성 도구에 붙여 넣는다.
>
> 목적: 지금 저장소의 실제 규칙을 지키며, `code_runner/` 안에만 숫자 재실행·대조 MVP를 구현하게 한다.

---

```text
너는 NAIS AI 해커톤 팀 LINK의 「숫자내력」 프로젝트에서 `code_runner/`만 담당하는 구현자다.

# 0. 제품 한 문장

숫자내력은 연구·사업 보고서에 있는 수치가 어떤 데이터·어떤 코드·어떤 실행 결과에서 왔는지 되짚어, 제출 전에 사람이 근거 있는 일치·불일치·보류 판단을 하도록 돕는 도구다.

이 작업의 목적은 웹 화면, 문서 파서, LLM이 아니라 다음 한 흐름을 신뢰성 있게 구현하는 것이다.

    Claim(JSON) + Trace(JSON) + 승인된 실행 계약(JSON)
                           ↓
                Docker 격리 가능 여부 확인
                           ↓
                  승인된 코드만 재실행
                           ↓
             출력값·코드·입력·로그 위치를 Evidence로 기록
                           ↓
        의미 조건 + 단위 + 반올림 + 허용오차를 적용해 1차 판정
                           ↓
               app이 그대로 표시할 Review Result JSON 반환

# 1. 먼저 반드시 읽을 파일

코드를 만들기 전 아래 파일을 전부 읽고 기존 관례를 따른다.

- `AGENTS.md`
- `README.md`
- `docs/USED.md`
- `data/samples/README.md`
- `data/samples/SOURCE_TEMPLATE.md`
- `code_runner/재실행대조_통합구현명세.md`
- `code_runner/` 아래의 기존 코드와 설정 파일 전체

읽고 나서 10줄 이내로 다음을 먼저 보고한다.

1. 현재 구현 언어·실행 도구·기존 파일 구조
2. 이번에 만들 최소 파일 목록과 책임
3. 기존 계약과 충돌하거나 사람이 결정해야 할 항목

질문 때문에 멈추지 말고, 아래 명세와 현재 파일에서 합리적으로 정해 구현한다. 단, 다른 파트 폴더를 바꾸는 선택만은 하지 않는다.

# 2. 팀 경계와 저장소 규칙

## 변경 가능 범위

- **수정·생성 가능:** `code_runner/` 내부
- **읽기만 가능:** `doc_parser/`, `app/`, `data/samples/`
- **수정 금지:** `doc_parser/`, `app/`, `data/samples/`, 루트 설정 파일

새 라이브러리·모델·외부 데이터를 추가해야 한다면 추가하지 말고 먼저 필요 사유를 보고한다. 이 저장소는 공개 저장소이므로 API 키, `.env`, 개인정보, 실제 연구 원문·민감 데이터는 절대 만들거나 커밋하지 않는다.

`git push --force`, 히스토리 재작성, 대량 삭제를 하지 않는다.

# 3. 도메인 모델: Claim, Trace, Evidence

## Claim: 보고서에 적힌 주장 수치

Claim은 문서 파서가 제공한다고 가정한다. `code_runner`는 Claim의 의미 조건을 확인하고 결과에 보존한다.

```json
{
  "claim_id": "C-042",
  "raw_value": "2.7배",
  "normalized_value": 2.7,
  "unit": "배",
  "metric": "처리 속도 개선 배수",
  "period": "2025년 실험",
  "population": "시험 데이터셋 A",
  "denominator": "기존 방법 평균 처리 시간",
  "location": {
    "section": "4. 연구성과",
    "page": 42,
    "source_type": "paragraph"
  }
}
```

## Trace: 같은 수치라는 연결 근거

```json
{
  "confidence": "high",
  "metric_match": "exact",
  "period_match": "exact",
  "population_match": "exact",
  "denominator_match": "exact",
  "formula_match": "exact",
  "link_reason": ["지표명 일치", "동일 데이터셋", "동일 분모 정의"]
}
```

**Trace가 없거나 `high`가 아니면 실행 결과가 있어도 `match`/`mismatch`를 만들지 않는다.**

## Execution Contract: 재실행 전에 확정된 입력

```yaml
claim_id: C-042

script:
  id: speed_benchmark_v1
  path: analysis/speed.py
  revision: git:abc123
  approved_by_team: true

input:
  files:
    - data/samples/benchmark_a.csv
  digest: sha256:...
  read_only: true

command:
  - python
  - analysis/speed.py
  - --input
  - data/samples/benchmark_a.csv

output:
  path: outputs/benchmark.json
  locator: /speedup
  expected_unit: 배

comparison:
  absolute_tolerance: 0.05
  relative_tolerance: null
  report_rounding_digits: 1

limits:
  network: disabled
  memory: 4GB
  cpu: 1
  timeout_seconds: 300
  isolation: docker_required
```

# 4. 절대 안전 규칙

아래는 기능보다 우선한다.

1. 사용자가 업로드한 임의 코드, 명령문, 경로를 실행하지 않는다.
2. 팀이 allowlist로 승인한 `script.id`와 고정된 인자 배열만 실행한다.
3. `shell=True`, 문자열 셸 명령 조합, `eval` 류 실행을 사용하지 않는다.
4. Docker 격리를 확인할 수 없으면 **절대 로컬 실행으로 우회하지 않는다.**
5. Docker 실행은 네트워크 차단, 입력 읽기 전용, 출력 폴더만 쓰기, 메모리 4GB 이하, CPU 제한, 300초 제한을 적용한다.
6. 원본 문서와 `data/samples/` 입력은 실행 중 수정하지 않는다.
7. API 키·개인정보·입력 원문 전체·값이 포함된 민감 로그를 결과 JSON 또는 로그에 남기지 않는다.
8. 코드 실행 오류, 의미 불일치, 값 불일치를 서로 같은 상태로 취급하지 않는다.

Docker가 없거나 실행 정책을 검증할 수 없을 때의 정답은 아래다.

```json
{
  "execution": {
    "status": "not_started",
    "isolation": "unavailable",
    "duration_seconds": null
  },
  "evidence": null,
  "comparison": {
    "status": "isolation_unavailable",
    "reason_codes": ["DOCKER_NOT_AVAILABLE"],
    "reason_summary": "안전한 Docker 격리 환경을 확인하지 못해 코드를 실행하지 않았습니다.",
    "possible_causes": []
  }
}
```

# 5. 반드시 반환할 상태

새 상태 이름을 만들지 말고 아래 enum만 사용한다.

| 상태 | 만드는 정확한 조건 |
|---|---|
| `match` | Trace가 `high`이고 지표·기간·대상·분모·산식이 모두 검증되며, 정규화·반올림 후 허용오차 이내 |
| `mismatch` | 위 의미·실행 조건은 충족하지만 정규화·반올림 후 허용오차 밖 |
| `not_comparable` | 지표·기간·대상·분모·산식·단위가 달라 비교가 성립하지 않음 |
| `evidence_incomplete` | 코드·입력·명령·출력 위치·출력값·승인 정보 중 재실행 근거가 부족 |
| `isolation_unavailable` | Docker 격리를 확인하지 못해 실행하지 않음 |
| `execution_failed` | 격리 실행을 시도했으나 종료 코드 오류, 시간 초과, 출력 파일 없음, JSON 파싱 실패 등 발생 |
| `needs_human_review` | 자동 연결 신뢰도가 낮거나 Claim 의미가 부족해 사람이 확인해야 함 |

판정은 반드시 다음 순서로 한다.

```text
필수 입력·실행 계약 존재 여부
  → 없음: evidence_incomplete
Docker 격리 가능 여부
  → 불가: isolation_unavailable (실행하지 않음)
승인된 코드·입력·명령·출력인지
  → 아니오: evidence_incomplete
Trace 의미 조건 확인
  → 명백한 불일치: not_comparable
  → 부족·낮은 신뢰도: needs_human_review
격리 실행
  → 실패: execution_failed
값 정규화·반올림·허용오차 비교
  → 이내: match
  → 초과: mismatch
```

다시 강조한다.

```text
실행 오류 ≠ mismatch
의미 불일치 ≠ mismatch
우연히 숫자가 같음 ≠ match
```

# 6. 단위·반올림 구현 범위

MVP는 아래 변환만 정확히 지원한다.

| 원문 | 정규화 단위 | 변환 |
|---|---|---|
| `87.5%` | `%` | 그대로 |
| `0.875` 비율 | `%` | × 100 |
| `2.7배` | `배` | 그대로 |
| `3.5억원` | `백만원` | × 100 |
| `3,500백만원` | `백만원` | 쉼표 제거 |
| `1,500,000원` | `백만원` | ÷ 1,000,000 |
| `1200ms` | `s` | ÷ 1,000 |

- `%`와 `%p`는 자동 변환하지 않는다.
- 보고서가 소수 첫째 자리로 표기됐으면 재실행 값을 같은 자릿수로 반올림해 비교한다.
- 결과에는 원문값, 정규화값, 변환 규칙, 반올림 자릿수, 절대/상대 허용오차, 절대/상대 차이를 남긴다.

예시:

```text
보고서 2.7배 / 재실행 2.714배 / 소수 첫째 자리 → match
보고서 2.7배 / 재실행 2.41배 / 허용오차 0.05 → mismatch
보고서 20% / 재실행 20%p → not_comparable 또는 needs_human_review
```

# 8. 구현 요구사항

최소 구조를 현재 저장소 관례에 맞춰 제안하고 구현한다. 구조가 아직 없다면 다음 책임 분리를 우선한다.

1. 입력 모델 검증
   - Claim, Trace, Execution Contract의 필수 필드 검사
   - 허용 루트 밖의 경로와 allowlist 밖 `script.id` 거절

2. 격리 사전 점검
   - Docker CLI와 필수 이미지/실행 조건 점검
   - 점검 실패 시 코드 실행 없이 `isolation_unavailable` 생성

3. 승인된 실행
   - 인자 배열 기반 Docker 실행
   - 네트워크 차단, 입력 읽기 전용, 출력 전용 쓰기 경로, 자원 제한 적용
   - 종료 코드·시간·출력 파일·출력 파싱 상태 수집

4. 출력 추출과 비교
   - 계약의 output path와 locator에서 숫자 1개 추출
   - 6절의 최소 단위 변환과 반올림·허용오차 적용
   - 5절 순서대로 상태와 reason code 생성

5. 부분 실패 보존
   - 한 Claim의 실패가 다른 Claim 결과를 무효화하지 않게 한다.
   - 실패한 경우에도 Claim, 실행하지 않은 이유, 안전한 범위의 메타데이터는 결과에 남긴다.

# 9. 테스트와 완료 조건

외부 네트워크, 외부 API, 비밀값, 실제 민감 자료 없이 반복 가능한 fixture를 `code_runner/` 안에서 만든다. Docker가 없는 개발 환경에서 실행을 흉내 내 성공시키지 않는다.

최소 테스트 사례:

1. `%` 변환과 반올림으로 `match`
2. `2.7배` 대 `2.41배`로 `mismatch`
3. 기간 또는 분모 불일치로 `not_comparable`
4. 실행 계약 누락으로 `evidence_incomplete`
5. Docker를 사용할 수 없을 때 실제 실행 없이 `isolation_unavailable`
6. 격리 실행의 시간 초과 또는 출력 파싱 실패로 `execution_failed`
7. Trace 신뢰도 부족으로 `needs_human_review`

구현 후에는 다음을 보고한다.

1. 변경 파일 목록과 각 파일 책임
2. 실행한 테스트 명령과 실제 결과
3. 대표 `match`, `mismatch`, `isolation_unavailable` JSON 각각 1개
4. Docker가 없는 경우 무엇을 실행하지 않았는지
5. 추가 라이브러리·외부 모델·외부 데이터가 있다면 `docs/USED.md` 기록이 필요한 이유
6. 아직 구현하지 않은 범위와 이유

# 10. 하지 말 것

- `app/` Streamlit 화면을 만들거나 수정하지 않는다.
- `doc_parser/`에서 문서를 직접 파싱하지 않는다.
- HWPX/PDF OCR, 로그인, 데이터베이스, 사용자 계정, 협업 기능을 추가하지 않는다.
- LLM API를 호출하거나 LLM이 수치를 계산·최종 판정하게 하지 않는다.
- 업로드 코드 자동 승인, 코드 자동 탐색 후 실행, 로컬 실행 우회를 하지 않는다.
- “재현 불가”, “격리 불가”, “근거 부족”을 `mismatch`로 뭉뚱그리지 않는다.

지금 구현을 시작하라. 변경 전 계획을 짧게 보인 뒤, 사용자 확인을 기다리지 말고 `code_runner/` 범위 안에서만 최소 구현과 테스트를 끝내라.
