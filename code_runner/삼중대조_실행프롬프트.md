# 2. 변경 범위와 안전 규칙

- 수정·생성은 `code_runner/` 안에서만 한다. `doc_parser/`, `app/`, `data/samples/`, 루트 설정은 읽기만 한다.

- 새 라이브러리·외부 데이터는 추가하지 않는다. 필요하면 구현 대신 사유를 보고한다.

# 4. 대조 순서: 반드시 원인 분리

## A. 공통 선행 검증

1. Claim의 지표·기간·대상·분모·산식이 충분히 추출됐는지 확인한다.
2. 데이터 파일의 존재·SHA-256·예상 행 수·필수 열·자료형을 `data_contract`와 비교한다.
3. 코드의 승인 여부·버전·선언한 입력 파일·고정 명령·출력 위치를 `execution_contract`와 비교한다.
4. Docker 격리 정책을 확인한다.

여기까지 실패하면 실행값으로 값 일치/불일치를 결론 내리지 않는다.

## B. 코드 ↔ 데이터 대조: “이 코드가 이 데이터를 분석했는가?”

아래를 별도의 `code_data_check`에 기록한다.

- 실행 시 읽은 파일 해시가 계약·업로드 데이터 해시와 같은가
- 코드가 선언하지 않은 파일을 읽거나, 선언한 파일을 읽지 않았는가
- 필수 열·자료형·행 수가 코드의 전제와 맞는가
- 코드의 필터, 기간, 대상 그룹, 결측치 처리, 중복 제거, 집계 기준이 계약의 `transform_summary`와 맞는가
- 코드 출력 단위와 계약의 출력 단위가 맞는가

파일 해시·입력 경로·핵심 스키마가 다르면 `CODE_DATA_INPUT_MISMATCH`다. 이 상태에서는 실행 결과가 보고서 수치와 우연히 같아도 `match`를 주지 않는다.

## C. 보고서 ↔ 데이터 대조: “보고서의 모집단·조건이 이 데이터에 존재하는가?”

아래를 별도의 `report_data_check`에 기록한다.

- 보고서의 기간과 데이터의 기간 범위가 일치하는가
- 보고서의 대상·표본·분모 정의가 데이터 열과 값으로 식별되는가
- 보고서 수치 산식에 필요한 변수·기준군·단위가 데이터에 존재하는가
- 데이터만으로 단순 검산 가능한 경우, 독립 계산값과 산식·필터·사용 열을 기록한다.

이 단계의 독립 계산은 원본 코드 재현이 아니다. 결과는 `independent_recalculation` 근거로 표시하고 자동 `match`/`mismatch`가 아니라 `needs_human_review`로 반환한다.

## D. 보고서 ↔ 코드 실행 결과 대조: “동일 조건에서 재현됐는가?”

B가 통과하고 Claim의 의미 조건(지표·기간·대상·분모·산식)이 코드 계약과 모두 `exact`일 때만 승인된 Docker 실행을 수행한다.

- 실행값을 **보고서 단위로 변환한 뒤** 보고서 반올림 자릿수로 반올림한다.
- 일반 수치: 허용오차 정책으로 대조한다.
- `p = 0.004`: 보고서 반올림 구간 정책으로 대조한다.
- `p < 0.001`: 등호 비교가 아닌 부등식 임계값 정책으로 대조한다.
- 단위·지표·분모·기간·대상이 하나라도 다르면 `not_comparable`이며 값 비교를 하지 않는다.

# 5. 최종 상태와 원인 코드

최종 상태는 기존 enum만 사용한다: `match`, `mismatch`, `not_comparable`, `evidence_incomplete`, `isolation_unavailable`, `execution_failed`, `needs_human_review`.

각 결과에 아래처럼 세 대조의 세부 결과와 reason code를 함께 반환한다.

```json
{
  "claim_id": "C-042",
  "status": "mismatch",
  "reason_codes": ["REPORT_CODE_VALUE_MISMATCH"],
  "report_data_check": {
    "status": "pass",
    "reason_codes": [],
    "checked_fields": ["period", "population", "denominator", "formula"]
  },
  "code_data_check": {
    "status": "pass",
    "reason_codes": [],
    "input_digests": [{"path": "data/samples/benchmark_a.csv", "sha256": "..."}]
  },
  "report_code_check": {
    "status": "mismatch",
    "reason_codes": ["REPORT_CODE_VALUE_MISMATCH"],
    "reported_value": {"raw": "2.7배", "normalized": 2.7, "unit": "배"},
    "executed_value": {"raw": 2.41, "report_unit": 2.4, "unit": "배"},
    "comparison_policy": {"mode": "rounded_interval", "rounding_digits": 1, "absolute_tolerance": 0.05}
  },
  "evidence_kind": "source_reproduction",
  "next_action": "보고서 표기값 또는 코드 버전·분석 조건을 확인하세요."
}
```

권장 reason code:

| 구분 | reason code |
|---|---|
| 보고서 의미 조건 부족 | `REPORT_SEMANTICS_INCOMPLETE` |
| 보고서-데이터 기간/대상/분모/산식 불일치 | `REPORT_DATA_SEMANTIC_MISMATCH` |
| 데이터 파일 해시·경로 불일치 | `CODE_DATA_INPUT_MISMATCH` |
| 데이터 스키마/행 수/필수 열 불일치 | `CODE_DATA_SCHEMA_MISMATCH` |
| 코드 변환·필터·집계 조건 불명확 | `CODE_DATA_TRANSFORM_UNKNOWN` |
| 실행값과 보고서값 불일치 | `REPORT_CODE_VALUE_MISMATCH` |
| 원본 코드·데이터·실행 근거 부족 | `ORIGINAL_PROOFS_INCOMPLETE` |
| 독립 재계산 결과 | `INDEPENDENT_RECALCULATION` |

우선순위는 다음과 같다.

```text
의미 조건 명백 불일치
  > 입력 데이터·코드 계약 불일치
  > Docker 격리 불가
  > 실행 실패
  > 수치 불일치

즉, 코드가 다른 데이터로 실행됐으면 “보고서와 코드 불일치”라고 단정하지 않는다.
```

# 6. 구현 산출물과 테스트

기존 `code_runner/` 모델·판정 흐름을 확장하되, UI·문서 파서·실제 데이터는 만들지 않는다.

최소 테스트는 다음을 포함한다.

1. 데이터 해시가 다르면 실행값이 같아도 자동 `match`가 아닌지
2. 코드가 선언 외 입력을 읽으면 `CODE_DATA_INPUT_MISMATCH`인지
3. 보고서 기간 또는 분모가 데이터/코드 조건과 다르면 값 비교 전에 `not_comparable`인지
4. 동일 데이터·동일 코드·동일 조건에서 `1.2초 ↔ 1200ms`가 보고서 단위 반올림 후 `match`인지
5. 세 대조가 통과했지만 값만 허용오차 밖이면 `REPORT_CODE_VALUE_MISMATCH`와 `mismatch`인지
6. 독립 재계산은 값이 같아도 `needs_human_review`와 disclosure를 남기는지

모든 결과에는 사람이 다음 행동을 알 수 있는 짧은 `next_action`을 넣는다. 코드 수정 후에는 관련 테스트·린트·타입 검사를 실행하고, 수정 파일·테스트 결과·남은 가정을 보고한다.
```

|---|---|

## 7-2. 오차 계산과 판정 표시

오차는 보고서에 표시된 단위로 변환한 뒤 계산한다.

```text
reported = 보고서 표기값을 정규화한 값
reproduced = 실행값을 보고서 단위로 변환한 값
error = reproduced - reported
absolute_error = abs(error)
```

- `absolute_error`와 `relative_error`를 가능한 경우 모두 저장한다.
- 보고서가 퍼센트이면 퍼센트와 퍼센트포인트를 구분한다. `87.5%`와 `87.46%`의 오차는 `0.04%p`다.
- 보고서가 `p < 0.001`이면 등호가 아니라 임계값 관계를 비교한다.
- 보고서 반올림 자릿수가 있으면 실행값을 같은 자릿수로 반올림한 값과 원시값을 모두 저장한다.
- 단위·지표·기간·대상·분모가 다르면 오차를 계산하지 않고 `not_comparable`로 표시한다.
- 세 대조가 모두 통과한 뒤 오차만 허용범위를 벗어나면 `mismatch`와 `REPORT_CODE_VALUE_MISMATCH`를 반환한다.

## 7-3. Streamlit 기본 화면

Streamlit은 결과 JSON을 읽어 다음 순서로 표시한다.

### 상단 요약

```text
전체 Claim | 일치 | 불일치 | 비교불가 | 증거부족 | 격리불가 | 사람검토
```

각 숫자는 현재 필터가 아니라 전체 결과 기준으로 계산하고, 사용자가 상태 필터를 선택하면 아래 표만 필터링한다.

### 기본 검토표

표의 열은 다음 순서를 지킨다.

| 열 | 표시 내용 |
|---|---|
| Claim ID | `C-001` |
| 지표 | `metric` |
| 원래 보고서 수치 | 원문값 + 정규화값 + 단위 |
| 재계산 수치 | 실행값 + 비교단위 |
| 오차 | 부호 있는 오차와 절대오차 |
| 허용오차 | 적용한 기준 |
| 판정 | 상태 enum과 색상 |
| 판정 근거 | 사람이 읽는 `reason` |
| 보고서 위치 | 페이지·표·행·열 |
| 코드 위치 | 파일·줄 범위 |
| 데이터 | 파일명과 해시 앞 12자리 |
| 다음 조치 | `next_action` |

표에는 원문 전체나 개인정보를 넣지 않는다. 긴 근거와 로그는 행 선택 후 상세 패널에서 상대 경로·해시·요약으로만 보여준다.

### Claim 상세 패널

행을 선택하면 아래 섹션을 펼쳐 보여준다.

1. **보고서 근거**: 원문 문장 또는 표 셀, 페이지, 표·행·열, 추출 문맥
2. **재계산 근거**: 데이터 파일·해시·스키마·행 수, 코드 파일·줄 범위, 출력 locator
3. **조건 대조**: 지표·기간·모집단·분모·산식별 `exact/mismatch/unknown`
4. **수치 대조**: 원시값, 단위 변환값, 반올림값, 오차, 허용오차, 적용 정책
5. **실행 정보**: run ID, 코드 revision, 환경 digest, 실행 상태
6. **판정 및 다음 조치**: reason code, 사람이 확인할 사항, `next_action`

## 7-4. 결과 파일 저장 규칙

- Claim 결과 전체는 `review_results.json`으로 저장한다.
- 실행 로그는 `run_id`별 별도 파일로 저장하되 원문·개인정보·비밀값은 기록하지 않는다.
- CSV는 화면 검토용 사본으로만 제공하고, 최종 근거는 JSON과 해시를 기준으로 한다.
- 결과 JSON에는 생성 시각, 명세 버전, 입력 데이터 계약 digest, 코드 revision을 기록한다.
- 결과에 값이 없거나 실행하지 못한 경우에도 행을 삭제하지 않고 상태와 이유를 저장한다.

권장 최상위 구조:

```json
{
  "schema_version": "nais-review-result-v1",
  "generated_at": "2026-09-30T22:01:13+09:00",
  "sample_id": "sample-07",
  "claims": [],
  "summary": {
    "total": 0,
    "match": 0,
    "mismatch": 0,
    "not_comparable": 0,
    "evidence_incomplete": 0,
    "isolation_unavailable": 0,
    "execution_failed": 0,
    "needs_human_review": 0
  }
}
```

## 7-5. 구현 완료 조건

다음 조건을 모두 만족해야 재실행 검토 구현 완료로 본다.

1. Claim 하나가 보고서 수치·재계산 수치·오차·판정·근거·위치를 한 행에 표시한다.
2. `match`와 `mismatch`는 보고서 단위·반올림·허용오차 정책을 표에 함께 표시한다.
3. `not_comparable`, `evidence_incomplete`, `isolation_unavailable`은 값 비교를 하지 않고 그 사유를 표시한다.
4. 표 행에서 보고서 위치, 데이터 파일·해시, 코드 파일·줄 범위, 실행 ID를 상세히 열람할 수 있다.
5. Streamlit에서 상태 필터와 CSV 다운로드를 제공한다.
6. JSON이 없는 경우 임의의 성공 수치를 만들지 않고 증거 부족 상태를 표시한다.
7. 샘플 데이터로 최소 6개 판정 테스트를 통과하고, 표에 테스트 결과와 남은 가정을 표시한다.
