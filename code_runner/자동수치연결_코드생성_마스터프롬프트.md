# 숫자내력 자동 수치 연결 엔진: 코드생성 마스터 프롬프트

> 사용법: 아래 코드 블록 전체를 Codex·Claude Code·Cursor에 붙여 넣는다.
>
> 목표: 사람이 “보고서의 15는 표 3에 있고 코드의 15와 비교해”라고 지정하지 않아도, 보고서·데이터·승인 코드 3종 입력에서 Claim 후보와 재실행 결과 후보를 자동 연결하고, 확실하지 않은 소수만 검토 큐로 보내는 `code_runner/` MVP를 구현한다.

---

```text
너는 NAIS AI 해커톤 팀 LINK의 「숫자내력」 프로젝트에서 `code_runner/`만 구현하는 엔지니어다.

# 0. 제품 정의와 성공 기준

숫자내력은 연구·사업 보고서의 수치가 어떤 데이터·어떤 분석 코드·어떤 재실행 결과에서 왔는지 자동으로 추적하는 검증 도구다.

사용자가 하는 일은 보고서 1개, 데이터 여러 개, 승인된 분석 코드 1개를 넣는 것뿐이다.
사용자가 숫자·표 위치·코드 줄·실행 ID를 수동 지정하게 만들지 않는다.

자동 흐름은 반드시 아래와 같다.

보고서 Claim 후보 전체 + 데이터 계약 + 승인 코드/실행 계약
  → Claim 후보의 문맥·위치·수치 의미 계약 수신
  → 코드 정적 분석 및 승인된 격리 재실행
  → 코드에서 수치 생성 이력(Provenance)과 출력값 후보 전체 수집
  → Claim ↔ Provenance 후보를 자동 연결·순위화
  → 수치 의미 계약을 필드별로 대조
  → 확실한 연결만 자동 판정
  → 애매하거나 근거가 부족한 후보만 검토 큐로 반환

성공은 “숫자 문자열이 같은 것을 많이 찾는 것”이 아니다.
같은 `15`라도 평균·합계·비율·중앙값·고유 개체 수·회귀계수가 다르면 값 비교를 수행하지 않는 것이 성공이다.

읽은 뒤 10줄 이내로 현재 구조와 변경할 파일·책임을 제시한 다음, 사용자 확인을 기다리지 말고 구현·테스트한다.

# 2. 팀 경계와 안전 규칙

- 수정·생성 가능: `code_runner/` 내부만
- 읽기만 가능: `doc_parser/`, `app/`, `data/samples/`
- 수정 금지: `doc_parser/`, `app/`, `data/samples/`, 루트 설정 파일
- 새 외부 라이브러리·API·모델·데이터는 추가하지 않는다. 필요하면 이유만 보고한다.
- 업로드된 임의 코드·명령·경로를 실행하지 않는다. 기존 승인 실행 계약과 allowlist만 사용한다.
- Docker 격리를 확인할 수 없으면 로컬 실행으로 우회하지 않는다.
- LLM이 수치를 계산하거나 최종 `match`/`mismatch`를 판정하게 하지 않는다.
- LLM 또는 문서 파서가 제공한 텍스트는 **후보·근거**일 뿐이다. 자동 판정은 아래의 결정적 게이트만 통과해야 한다.

문서 HWPX/PDF/DOCX 파싱은 `doc_parser`의 책임이다. `code_runner`는 파서가 제공하는 Claim 후보 JSON을 받아 자동 연결한다. 파서가 아직 완성되지 않았어도 fixture JSON으로 자동 연결 엔진을 구현·검증한다.

# 4. 코드 Provenance 자동 수집

승인된 코드의 정적 분석과 격리 재실행에서 출력 숫자 하나만 뽑지 말고, 수치가 생성된 이력을 `ProvenanceCandidate`로 수집한다.

```json
{
  "provenance_id": "prov-014",
  "run_id": "run-20261001-001",
  "value": 15.02,
  "unit": "점",
  "output": {
    "path": "outputs/result.json",
    "locator": "/metrics/seoul_mean_satisfaction"
  },
  "code_evidence": {
    "script_path": "analysis/report.py",
    "code_revision": "git:abc123",
    "line_start": 81,
    "line_end": 87,
    "expression_text": "filtered['satisfaction_score'].mean()"
  },
  "input_evidence": {
    "files": ["data/survey.csv"],
    "digest": "sha256:data...",
    "columns": ["region", "year", "satisfaction_score"]
  },
  "quantity_semantics": {
    "quantity_kind": "mean",
    "aggregation": {
      "operator": "mean",
      "group_by": [],
      "row_scope": "respondent",
      "weight_column": null,
      "distinct_key": null
    },
    "numerator": "sum(satisfaction_score for filtered respondents)",
    "denominator": "count(filtered respondents with non-missing satisfaction_score)",
    "filters": ["region=Seoul", "year=2025"],
    "missing_value_policy": "exclude_missing",
    "transformations": [],
    "estimate_method": "arithmetic_mean",
    "formula_canonical": "mean(satisfaction_score) WHERE region=Seoul AND year=2025 AND satisfaction_score IS NOT NULL"
  }
}
```

지원 가능한 언어/패턴은 현재 저장소의 범위로 제한한다. 언어별 AST·실행 추적이 불가능한 코드에서는 수치 의미를 지어내지 말고 `unknown` 근거를 남겨 검토 큐로 보낸다.

코드 변수명 `avg`, `total`, 출력 키 이름만으로 집계식을 확정하지 않는다. 집계 함수/연산식, 입력 열, 필터, 가중치, 결측 처리, 출력 locator와 코드 줄 범위를 근거로 보존한다.

# 5. 자동 연결 엔진

각 Claim 후보와 Provenance 후보의 전수 조합을 무조건 보여 주지 말고, 결정적 후보 생성 → 의미 게이트 → 점수화 → 결과 분류 순서로 처리한다.

## 5-1. 후보 생성

다음 중 하나 이상이 근거로 있는 후보만 연결 후보로 만든다.

- 정규화된 지표명/표 제목/출력 키의 토큰 교집합
- 보고서 단위와 출력 단위가 같거나 명시적으로 변환 가능
- 보고서 문맥의 변수명과 코드 입력 열/출력 키의 연결 근거
- 기간·대상·필터 표현의 일치 근거
- 동일 데이터 파일·해시 또는 승인 실행 계약의 입력 연결

값이 같다는 사실만으로 후보를 만들지 않는다. 단, 값이 다른데 지표·의미 근거가 강하면 후보로 유지해야 한다. 불일치를 발견하는 것이 목적이기 때문이다.

## 5-2. 하드 의미 게이트

아래 필드 각각을 `exact`, `mismatch`, `unknown`으로 비교하고 `SemanticComparison`에 근거 문자열·원문 위치·코드 줄 범위를 남긴다.

```text
quantity_kind
aggregation.operator
aggregation.group_by / row_scope
numerator / denominator
filters / population / period
missing_value_policy
weight_column / distinct_key
transformations / estimate_method
unit 및 변환 가능성
```

판정 규칙은 절대 바꾸지 않는다.

```text
mismatch 하나 이상 → not_comparable
unknown 하나 이상 → needs_human_review
모든 필드 exact + 승인 실행/입력/Trace 게이트 통과 → 값 비교 가능
```

`not_comparable`과 `needs_human_review`에서는 `numeric_difference=null`이다. 동일한 15라도 초록색 일치 상태나 0 차이를 만들지 않는다.

## 5-3. `not_comparable` 뒤의 자동 복구 탐색

최초 후보가 `not_comparable` 또는 `needs_human_review`라고 해서 Claim 전체를 즉시 검토 큐로 끝내지 않는다. `수치의미계약_대조기준.md`의 자동 복구 규칙을 따르되, 최초 후보와 불일치 사유는 삭제하지 않고 `recovery_history`에 보존한다.

복구 순서는 고정한다.

```text
1. direct_alternative_output_search
   - 같은 승인 실행의 출력 locator, 코드 줄 범위, 명시적 mean/sum/rate/ratio 연산식에서 대체 Provenance 후보 탐색

2. evidence_enrichment
   - 보고서의 표 제목·각주·인접 문장, 코드의 인접 필터·결측·가중치 처리를 다시 읽어 unknown 근거 보강

3. safe_derived_calculation
   - 동일 실행에서 명시적으로 수집된 분자·분모 또는 sum·valid_count만 사용해 평균/비율 후보 재구성
```

처리 규칙은 아래와 같다.

```text
직접 대체 출력 후보 + 모든 의미 필드 exact + high 연결 점수
  → 최초 후보의 not_comparable을 기록한 채, 대체 후보로 자동 재판정 가능

unknown이 근거 보강 후에도 남음
  → needs_human_review

safe_derived_calculation만 가능
  → derived_provenance로 저장, needs_human_review
  → 원본 코드의 직접 출력 match/mismatch로 표시 금지

대체 후보의 필터·가중치·기간·분모·결측 처리 중 mismatch 존재
  → 자동 복구 금지, 최초 상태 유지
```

다음 행동은 금지한다.

- 최초 후보의 불일치 이력 삭제 또는 덮어쓰기
- 변수명·값 근접성만으로 평균/합계 후보 확정
- 코드 수정·임의 명령 실행·미승인 재실행
- 산술 재구성값을 원본 직접 재현 결과로 표시

`recovery_history` 최소 필드는 다음과 같다.

```json
{
  "initial_provenance_id": "prov-sum-015",
  "initial_status": "not_comparable",
  "initial_reason_codes": ["AGGREGATION_OPERATOR_MISMATCH"],
  "attempted": true,
  "strategy": "direct_alternative_output_search",
  "searched_code_locations": ["analysis/report.py:70-105"],
  "replacement_provenance_id": "prov-mean-014",
  "outcome": "direct_candidate_found"
}
```

## 5-4. 연결 신뢰도와 중복 후보 처리

하드 게이트를 통과한 후보만 아래 결정적 근거 점수를 사용한다. 임의의 모델 점수만으로 자동 확정하지 않는다.

| 근거 | 점수 |
|---|---:|
| 지표/출력 키/표 제목의 정규화 일치 | 25 |
| 기간·대상·필터 근거 일치 | 20 |
| 집계·분자·분모·결측·가중치 의미가 모두 exact | 25 |
| 입력 데이터 계약·해시 연결 | 15 |
| 코드 줄 범위와 출력 locator가 존재 | 10 |
| 단위 변환·반올림 정책이 명시됨 | 5 |

```text
95점 이상 + 2등 후보와 15점 이상 차이 + 모든 하드 게이트 exact
  → auto_linked_high

70~94점 또는 1·2등 후보 점수 차이 15점 미만
  → review_queue: ambiguous_link

후보 없음
  → review_queue: no_provenance_candidate

의미 mismatch/unknown
  → 해당 후보의 not_comparable / needs_human_review를 보존하고 검토 큐에 사유 표시
```

점수는 후보 순위 결정용이다. `auto_linked_high`가 아니면 `match`/`mismatch`를 만들지 않는다.

# 6. 값 비교와 상태

`auto_linked_high`이고 의미·실행 게이트가 모두 통과한 연결만 기존 `comparison.py`의 단위 환산 → 보고서 표기 자릿수 반올림 → 허용오차 비교를 호출한다.

출력 상태는 기존 enum을 사용한다.

| 조건 | 상태 |
|---|---|
| 모든 의미 조건 exact, 자동 연결 high, 값이 허용오차 이내 | `match` |
| 모든 의미 조건 exact, 자동 연결 high, 값이 허용오차 밖 | `mismatch` |
| 의미 필드 mismatch, 직접 대체 후보 없음 | `not_comparable` |
| 최초 후보 mismatch 후 직접 대체 후보가 모든 게이트 통과 | 대체 후보로 `match` 또는 `mismatch`, 복구 이력 보존 |
| 의미 필드 unknown 또는 후보 연결 모호 | `needs_human_review` |
| 동일 실행 수치로 안전하게 산술 재구성만 가능 | `needs_human_review` + `DERIVED_PROVENANCE` |
| 보고서 Claim 후보가 있으나 코드 후보 없음 | `needs_human_review` + `NO_PROVENANCE_CANDIDATE` |
| 실행 불가/실패/근거 부족 | 기존 `isolation_unavailable` / `execution_failed` / `evidence_incomplete` |

평균 15점과 합계 15점의 필수 결과는 아래다.

```json
{
  "status": "not_comparable",
  "reason_codes": [
    "AGGREGATION_OPERATOR_MISMATCH",
    "DENOMINATOR_MISMATCH",
    "FORMULA_MISMATCH"
  ],
  "numeric_difference": null,
  "reason_summary": "두 값 모두 15점이지만 보고서는 유효응답자 평균, 재실행은 점수 합계입니다. 값 비교를 수행하지 않았습니다."
}
```

# 7. 반환 계약: 자동 결과와 검토 큐를 함께 반환

`AutoLinkReviewResult`는 문서의 모든 Claim 후보에 대해 결과를 반환한다. 자동 판정 성공 수만 반환해 미연결 Claim을 숨기면 안 된다.

```json
{
  "document_sha256": "sha256:report...",
  "run_id": "run-20261001-001",
  "summary": {
    "claim_candidates": 42,
    "auto_linked_high": 31,
    "match": 25,
    "mismatch": 2,
    "not_comparable": 1,
    "needs_human_review": 14,
    "no_provenance_candidate": 3
  },
  "results": [
    {
      "claim_candidate_id": "claim-001",
      "provenance_id": "prov-014",
      "link_state": "auto_linked_high",
      "link_score": 100,
      "status": "match",
      "recovery_history": [],
      "semantic_comparisons": [],
      "numeric_comparison": {
        "report_value": "15점",
        "evidence_in_report_unit": 15.02,
        "rounded_evidence": 15.0,
        "difference": 0.0
      },

# 8. 구현 범위와 구조

기존 파일을 최대한 재사용하며 최소한 아래 책임을 분리한다.

1. `auto_link_models.py`
   - ClaimCandidate, ProvenanceCandidate, QuantitySemantics, SemanticComparison, AutoLink, ReviewQueueItem 모델
2. `auto_linking.py`
   - 정규화, 후보 생성, 하드 의미 게이트, 결정적 점수화, 중복 후보 처리, 제한된 자동 복구 탐색
3. 기존 `triple_workflow.py` 또는 얇은 orchestration 모듈
   - 승인 실행 Evidence/Provenance를 연결하고 기존 값 비교를 호출
4. `test_auto_linking.py`
   - 외부 API·Docker 없이 fixture 기반으로 아래 테스트를 수행

현재 모델과 충돌하면 별도 타입을 만든 뒤 어댑터를 두고, 기존 공개 API를 깨지 않는다. `Any`, 무음 예외 처리, 숨은 기본값, 문자열 status를 새로 만들지 않는다.

# 9. 필수 테스트

최소 아래 사례를 모두 자동화한다.

1. 동일 평균·분모·필터·결측 처리이고 반올림 후 일치 → `auto_linked_high` + `match`
2. 동일 의미이나 실행값이 허용오차 밖 → `auto_linked_high` + `mismatch`
3. 보고서 평균 15 / 실행 합계 15 → `not_comparable`, 차이 null
4. 보고서 15% / 실행 15명 → `not_comparable`
5. 단순 평균 / 가중 평균 → `not_comparable`
6. 보고서 결측 처리 unknown → `needs_human_review`, 차이 null
7. 기간 또는 필터 mismatch → `not_comparable`
8. 그룹 평균 / 전체 평균, 그룹 분자·분모 부족 → `needs_human_review`
9. 강한 지표 근거가 있어 값이 달라도 올바른 후보를 연결하고 `mismatch`를 찾음
10. 1등·2등 후보 점수 차이가 15 미만 → `AMBIGUOUS_LINK`, 자동 판정 없음
11. 보고서 Claim 후보에 코드 출력 후보가 없음 → `NO_PROVENANCE_CANDIDATE`
12. 집계 함수/필터를 코드에서 증명할 수 없음 → 의미 필드 unknown, 자동 일치 금지
13. 모든 결과의 보고서 위치·코드 줄 범위·출력 locator가 보존됨
14. 기존 `code_runner` 테스트가 모두 계속 통과함
15. 최초 합계 후보가 `not_comparable`이지만 같은 승인 실행의 평균 직접 출력 후보를 자동 발견 → 최초 이력 보존 후 대체 후보로 `match` 또는 `mismatch`
16. `sum`과 `valid_count`만으로 평균을 재구성 → `DERIVED_PROVENANCE` + `needs_human_review`, 직접 재현 `match` 금지
17. 대체 후보가 존재해도 기간·필터·가중치 mismatch이면 자동 복구하지 않음
18. 복구 이력에 최초 후보·탐색 코드 위치·전략·교체 후보·결과가 모두 보존됨
