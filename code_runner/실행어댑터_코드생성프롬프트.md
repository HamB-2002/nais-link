# 구현 목표

기존 `evaluate_triple(TripleComparisonRequest)`는 판정 엔진이다. 이 엔진을 바꾸거나 규칙을 복제하지 말고, 실제 파일과 격리 실행에서 얻은 근거를 조립해 한 번 호출하라.

다음 공개 진입점을 만든다.

    run_triple_review(upload_bundle, approved_contract, claim, trace, tolerance)

반환값은 기존 `TripleReviewResult`다. 예외를 호출자에게 노출하지 말고, 예상 가능한 파일·계약·Docker·출력 실패는 기존 `ReviewStatus`와 reason code로 변환한다.

# 구현 모듈

1. `file_inspector.py`
   - `inspect_csv`는 업로드 루트 안의 CSV만 검사한다.
   - `hashlib.sha256`을 스트리밍 계산한다.
   - `csv` 표준 라이브러리로 헤더, 행 수, 열 목록을 수집한다.
   - 원문 행·개인정보를 반환/로그하지 않는다.
   - 루트 탈출, 심볼릭 링크, 중복 열, CSV 파싱 실패, 크기·행 제한을 안전하게 거부한다.

2. `execution_contract.py`
   - 계약은 서버 allowlist에서 선택된 `script_id`, image digest, 고정 command 배열, 선언 입력, 출력 JSON Pointer, 리소스 제한을 가진 타입이다.
   - 업로드된 command/path/image 문자열로 계약을 덮어쓸 수 없게 한다.
   - 승인되지 않은 script/image/command는 `evidence_incomplete`로 반환한다.

3. `docker_runner.py`
   - Docker가 없으면 `isolation_unavailable`을 반환하고 절대로 로컬 실행하지 않는다.
   - `subprocess.run`의 인자 배열과 `shell=False`만 사용한다.
   - `--network none`, `--read-only`, `--cap-drop ALL`, `no-new-privileges`, CPU/메모리/PID/시간 제한, read-only code/input mount, output-only writable mount를 모두 적용한다.
   - 이미지 태그가 아니라 digest만 허용한다.
   - timeout, non-zero exit, output 없음, 잘못된 JSON, 잘못된 JSON Pointer를 `execution_failed`로 구분한다.
   - `stdout`/`stderr` 원문, 환경 변수, 데이터 본문을 결과에 담지 않는다.

4. `adapter.py`
   - 데이터 파일 검사 → 계약 검증 → Docker 실행 → JSON Pointer 숫자 추출 → `TripleComparisonRequest` 조립 → `evaluate_triple` 호출 순서다.
   - 보고서↔데이터 및 코드↔데이터 불일치가 있으면 수치 일치/불일치를 만들지 않는다.
   - JSON Pointer `/speedup`만 지원한다. JSONPath, eval, 문자열 쉘 명령은 금지한다.
   - 숫자는 `Decimal`로 변환하고 NaN/Infinity/배열/객체/문자열은 거부한다.

# 실패 우선순위

    파일·계약 부족 → evidence_incomplete
    Docker 불가 → isolation_unavailable
    컨테이너/출력 실패 → execution_failed
    보고서-데이터·코드-데이터 조건 불일치 → 엔진의 보류/비교불가
    모든 조건 통과 → 기존 엔진의 match/mismatch

# 절대 금지

- `shell=True`
- `eval`, `exec`, JSONPath 표현식
- 호스트에서 업로드 코드 실행
- 임의 Docker image/tag, 업로드 command 실행
- 네트워크가 켜진 컨테이너
- 입력/코드 쓰기 가능 마운트
- 데이터 원문·비밀값·환경 변수·무제한 로그 저장
- `app/`, `doc_parser/`, `data/samples/` 수정
